# 공통 (앱 전역 기능)

## 개요
로그인 사용자만 쓸 수 있는 개인용 기록 서비스의 전역 동작을 다룬다. 로그인·세션 복원·로그아웃, 권한(관리자/일반) 판단, 보호 화면 접근 제어, 기기(데스크톱 `/main`, 모바일 `/mobile`) 분기, 전역 내비게이션, 그리고 모든 화면이 공유하는 확인 절차·빈/에러/로딩 상태·파일 업로드·테마 규칙을 정의한다. 각 도메인 문서는 이 문서의 규칙을 전제로 한다.

## URL
`/main/*` 은 데스크톱, `/mobile/*` 은 모바일이며 **동일한 뒤쪽 경로를 양쪽이 모두 갖는다** (아래 표는 뒤쪽 경로 기준). 로그인·404 를 제외한 모든 화면은 로그인 필요.

| 경로 (/main, /mobile 공통 뒤쪽) | 화면 의미 | 접근 권한 | 비고 |
|---|---|---|---|
| `/` (접두사 없는 최상위) | 기기 판별 후 `/main` 또는 `/mobile` 로 이동 | 누구나 | 화면 없음, 즉시 이동(히스토리 대체) |
| `/login` | 로그인 | 비로그인 (로그인 상태면 즉시 이동) | `redirect` 쿼리 지원 |
| `/404` | 페이지를 찾을 수 없음 | 누구나(공개) | 정의되지 않은 모든 경로의 도착지 |
| (빈 경로 = `/main`, `/mobile`) | 홈 | 로그인 | HOME 문서 |
| `/map` | 나들이 목록 | 로그인 | |
| `/map/register` | 나들이 기록하기 | 로그인 | 모바일은 상세형 화면 틀 |
| `/map/:id` | 나들이 상세 | 로그인 | 모바일은 상세형 화면 틀 |
| `/travel` | 여행 목록 | 로그인 | |
| `/travel/register` | 새 여행 등록 | 로그인 | 모바일은 상세형 화면 틀 |
| `/travel/:id` | 여행 상세 | 로그인 | 모바일은 기본 화면 틀(하단 내비 유지) |
| `/travel/:id/edit` | 여행 수정 | 로그인 | 모바일은 상세형 화면 틀 |
| `/calendar` | 달력(월) | 로그인 | |
| `/calendar/week` | 달력(주) | 로그인 | |
| `/shoesRecom` | 신발 목록(추천) | 로그인 | |
| `/:brand/:shoesName` | 신발 상세 | 로그인 | 예약어(login, map, calendar, shoesRecom, travel, inspection, profile, main, mobile)는 브랜드로 쓸 수 없음. 모바일은 상세형 화면 틀 |
| `/profile` | 프로필 | 로그인 | **데스크톱은 화면 없음: `/main`(홈)으로 즉시 이동**. 데스크톱의 프로필 기능은 헤더 메뉴의 단계형 창으로 제공. 모바일은 마이페이지 화면(상세형 틀) |
| `/profile/verify` | 본인 확인 | 로그인 | 데스크톱은 `/main` 으로 이동(화면 없음). 모바일 전용 화면 |
| `/profile/edit` | 사용자 정보 수정 | 로그인 | 데스크톱은 `/main` 으로 이동(화면 없음). 모바일 전용 화면 |
| `/inspection` | 임장 지역 목록 | 로그인 | |
| `/inspection/register` | 임장 등록 | 로그인 | |
| `/inspection/questions` | 임장 질문 관리 | **관리자만** | 일반 사용자는 `/404` 로 이동 |
| `/inspection/:areaId` | 임장 지역 상세 | 로그인 | |
| `/inspection/:areaId/property/:propertyId` | 매물 상세 | 로그인 | |
| `/inspection/:areaId/visit/:visitId/edit` | 방문 기록 수정 | 로그인 | |
| `/inspection/:areaId/visit/:visitId/property/:propertyId/edit` | 매물 수정 | 로그인 | |

- 보호 대상 화면은 로그인·404 를 제외하고 **22개**(홈 포함: 홈, 나들이 3, 여행 4, 달력 2, 신발 2, 프로필 3, 임장 7).
- `/main/`·`/mobile/` 아래 정의되지 않은 경로는 해당 기기의 `/404` 로, 접두사 자체가 없는 알 수 없는 경로(예: `/foo`)는 `/main/404` 로 이동한다.
- 모든 URL 은 리디자인 후에도 유지 대상이다.

## 기능 목록

### COM-01 기기 판별과 최상위 경로 이동
- **대상 사용자**: 누구나
- **진입 경로**: 접두사 없는 최상위 주소(`/`) 접속
- **흐름**: 1. 브라우저 사용자 에이전트가 Android / iPhone / iPad / iPod / webOS / BlackBerry / IEMobile / Opera Mini 중 하나면 모바일, 아니면 데스크톱으로 판정 2. 판정에 따라 `/mobile` 또는 `/main` 으로 즉시 이동(뒤로가기 기록 남기지 않음) 3. 이후 보호 화면 규칙(COM-04)이 적용된다.
- **표시 데이터**: 없음
- **상태**: 판정 즉시 이동. 로딩/에러 없음.
- **결과**: `/main` 또는 `/mobile` 홈(미로그인이면 로그인 화면으로 이어짐)
- **정책·예외 규칙**: 판별은 화면 폭이 아니라 사용자 에이전트 문자열 기준이며 접속 시 최초 한 번만 수행한다. 이후 `/main` 과 `/mobile` 사이를 자동으로 오가는 로직은 없다(사용자가 다른 쪽 주소를 직접 열면 그대로 열린다). 데스크톱/모바일 화면 간 전환 링크도 없다.
- **데스크톱/모바일 차이**: 없음(분기 자체가 기능)

### COM-02 로그인
- **대상 사용자**: 비로그인
- **진입 경로**: `/main/login`, `/mobile/login` 직접 접속, 또는 보호 화면 접근 시 자동 이동(COM-04), 로그아웃 후 이동(COM-06)
- **흐름**: 1. 아이디·비밀번호 입력 2. "로그인" 제출 3. 성공하면 세션이 저장되고 로그인 상태가 되며 `redirect` 쿼리가 유효하면 그 주소로, 아니면 해당 기기 홈으로 이동(히스토리 대체) 4. 실패하면 같은 화면에 오류 문구 표시
- **입력 항목**:

| 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
|---|---|---|---|---|
| 아이디 (자리표시: "아이디를 입력해 주세요") | 텍스트, 브라우저 자동완성(username) | 예 | 필수(브라우저 기본 검증). 입력값 지우기 버튼(값이 있을 때만 활성, 누르면 비우고 해당 입력에 포커스) | 실패 시 공통 문구 ↓ |
| 비밀번호 (자리표시: "비밀번호를 입력해 주세요") | 비밀번호, 자동완성(current-password) | 예 | 필수. 입력값 지우기 버튼 동일 | 실패 시 공통 문구 ↓ |

  - 현재 문구(로그인 실패, 원인 불문 동일): "아이디 또는 비밀번호를 다시 확인해 주세요."
  - 화면 제목 영역에 서비스 로고와 서비스 이름이 표시된다.
- **표시 데이터**: 로고, 서비스 이름, 입력 2개, 오류 영역
- **상태**: 처리 중 — 로그인 버튼이 로딩 상태(중복 제출 방지). 에러 — 입력 유지한 채 알림성 오류 문구. 이미 로그인 상태로 이 화면에 오면 입력 없이 즉시 이동 대상으로 이동. 성공 — 이동.
- **결과**: 세션 저장(액세스 토큰은 메모리에만, 사용자 이름/아이디/권한 목록은 세션 저장소에 보관), 프로필 본인확인 허용 기록 폐기.
- **정책·예외 규칙**:
  - `redirect` 쿼리 허용 조건: `/` 로 시작하고 `//` 로 시작하지 않으며, 현재 기기 접두사(`/main` 또는 `/mobile`) 범위 내여야 한다. 조건 불충족이면 기기 홈으로 이동.
  - 예외: `redirect` 가 `/stock` 으로 시작하는 경우(같은 도메인의 별도 앱)는 SPA 이동이 아닌 **전체 페이지 이동**으로 해당 주소로 보낸다.
  - 네트워크 오류·서버 오류·자격 증명 오류를 구분하지 않고 같은 문구를 보인다.
  - 로그인 화면은 내비게이션/헤더가 없는 공개 틀(로고+폼만)이다.
- **데스크톱/모바일 차이**: 없음(경로 접두사만 다르고 `redirect` 도 같은 기기 접두사만 허용)

### COM-03 세션 복원 (새로고침·재방문)
- **대상 사용자**: 로그인 사용자(자동)
- **진입 경로**: 앱 최초 로드 또는 새로고침(자동 수행, 사용자 조작 없음)
- **흐름**: 1. 앱 로드 시 세션 저장소의 사용자 정보(이름/아이디/권한)를 읽는다. 액세스 토큰은 저장하지 않으므로 이 시점에는 로그인 상태가 아니다. 2. 토큰이 없으면 서버에 세션(쿠키) 기반 토큰 재발급을 한 번 요청한다. 3. 성공하면 토큰·사용자 정보를 갱신하고 로그인 상태가 된다. 4. 실패하면 저장된 사용자 정보도 지우고 비로그인 상태가 된다.
- **표시 데이터**: 복원 중 안내 문구 — 현재 문구: "세션을 확인하고 있어요." (보호 화면 자리에 표시, 상태 알림 역할)
- **상태**: 복원 중(저장소 읽기 전 포함) — 보호 화면 내용을 보여주지 않고 위 문구만 표시. 성공 — 원래 요청 화면 표시. 실패 — 로그인 화면으로 이동(COM-04).
- **결과**: 새로고침해도 서버 세션이 유효하면 로그인 유지.
- **정책·예외 규칙**: 복원 시도는 비로그인 상태에서 한 번만 한다(실패 후 자동 재시도 없음). 프로필 조회 등 사용자 데이터 요청은 토큰이 확보된 뒤에만 나간다. 복원 시작/성공/실패 모두 프로필 본인확인 허용 기록을 폐기한다.
- **데스크톱/모바일 차이**: 없음

### COM-04 보호 화면 접근 제어와 로그인 후 복귀
- **대상 사용자**: 비로그인
- **진입 경로**: 로그인 없이 보호 화면 URL 접속
- **흐름**: 1. 복원 중이면 COM-03 의 안내 문구 2. 복원이 끝났는데 로그인 상태가 아니면 같은 기기의 로그인 화면으로 이동(히스토리 대체) 3. 이때 원래 주소(경로+쿼리+해시)를 `redirect` 쿼리에 담는다 4. 로그인 성공 시 COM-02 의 규칙대로 원래 주소로 복귀
- **상태**: 복원 중 / 비로그인(이동) / 통과
- **결과**: `/main/...` 접근은 `/main/login?redirect=...`, `/mobile/...` 접근은 `/mobile/login?redirect=...`
- **정책·예외 규칙**: 로그인 화면과 404 화면은 보호 대상이 아니다. 접두사 없는 최상위 `/` 는 COM-01 이 먼저 처리한다.
- **데스크톱/모바일 차이**: 없음 (로그인 경로만 기기별)

### COM-05 권한(관리자/일반) 판단
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 권한 제한 화면 접근
- **흐름**: 1. 로그인 응답의 권한 목록(관리자 / 일반 / 그 외 알 수 없는 값은 무시)을 사용자 정보로 보관 2. 관리자 전용 화면(`/inspection/questions`) 접근 시 권한 목록에 관리자가 없으면 **로그인 화면이 아니라 404 화면**으로 이동(히스토리 대체)
- **상태**: 권한 없음 — 404 화면
- **정책·예외 규칙**: 관리자 전용으로 코드에서 확인되는 경로는 임장 질문 관리 하나뿐이다. 전역 내비게이션에는 관리자 전용 메뉴가 없고(해당 화면은 임장 영역 내부 진입으로 추정 — INSP 문서 참조), 권한 없는 사용자에게 메뉴를 숨기는 전역 로직은 없다.
- **데스크톱/모바일 차이**: 없음

### COM-06 로그아웃
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 데스크톱 — 헤더 우측 프로필 버튼 메뉴의 "로그아웃". 모바일 — 마이페이지(`/mobile/profile`)의 "로그아웃" 버튼
- **흐름**: 1. 버튼 누름(확인 절차 없음, 즉시 실행) 2. 프로필 본인확인 허용 기록 폐기 3. 서버에 로그아웃 요청 4. 성공·실패 상관없이 로컬 세션(토큰·사용자 정보)과 모든 캐시된 서버 데이터를 지움 5. 해당 기기의 로그인 화면으로 이동(히스토리 대체)
- **상태**: 처리 중 — 버튼 문구가 "로그아웃 중…" 으로 바뀌고 비활성. 서버 요청 실패해도 사용자에게 오류를 보이지 않고 로그아웃이 완료된다.
- **결과**: 로그인 화면. 로그인 화면에는 `redirect` 쿼리가 붙지 않는다.
- **데스크톱/모바일 차이**: 진입 위치만 다름(위 진입 경로)

### COM-07 404 화면
- **대상 사용자**: 누구나
- **진입 경로**: 존재하지 않는 경로, 권한 부족(COM-05)
- **표시 데이터**: 제목 현재 문구: "페이지를 찾을 수 없어요." / 설명 현재 문구: "찾으시는 화면이 없어요. [서비스명] 홈으로 다시 이동해 보세요." / 동작 "홈으로 돌아가기"(해당 기기 홈으로 이동)
- **상태**: 단일 상태
- **정책·예외 규칙**: 로그인 없이도 열린다. 데스크톱은 헤더·푸터 틀 안에, 모바일은 상단바·하단 내비 틀 안에 표시된다.
- **데스크톱/모바일 차이**: 없음

### COM-08 라우트 로딩 표시
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 화면(페이지 단위 코드)을 처음 열 때 지연 로딩되는 동안
- **표시 데이터**: 현재 문구: "페이지를 불러오는 중입니다." (보조 기술용 이름 "route-loading")
- **상태**: 로딩 중에만 표시, 로딩이 끝나면 해당 화면으로 교체. 로딩 실패에 대한 별도 화면은 없다.
- **데스크톱/모바일 차이**: 없음

### COM-09 데스크톱 전역 헤더
- **대상 사용자**: 로그인 사용자 (`/main/*` 보호 화면과 `/main/404` 에 표시. 로그인 화면에는 없음)
- **진입 경로**: 모든 데스크톱 화면 상단
- **기능**:
  1. **로고(서비스 홈 링크)**: 누르면 `/main`. 접근성 이름 "[서비스명] 홈으로 이동"(의미: 서비스 홈으로 이동)
  2. **주요 메뉴** (접근성 이름 "주요 메뉴"), 순서 고정: 홈(`/main`, 정확히 일치할 때만 활성) → 여행(`/main/travel`) → 나들이(`/main/map`) → 임장(`/main/inspection`) → 달력(`/main/calendar`). 현재 위치에 해당하는 메뉴는 활성 표시. **신발 메뉴는 데스크톱 헤더에 없다**(신발 진입은 홈의 "더보기"의 "신발 기록" 링크)

- **상태**:
  - 프로필 이미지 로딩 중 — 아바타가 로딩 표시. 이미지 없음 또는 실패 — 기본 아바타. 이름은 프로필 조회 결과를 우선하고 없으면 로그인 시점 이름을 사용.
  - 메뉴 열림 동안: 바깥을 누르거나 Esc 로 닫힘(Esc 시 프로필 버튼으로 포커스 복귀), 화면 이동(경로 변경) 시 자동 닫힘, 열리면 첫 항목에 포커스, 위/아래 화살표·Home·End 로 항목 이동(순환).

- **데스크톱/모바일 차이**: 데스크톱 전용

### COM-11 모바일 상단바 · 하단 내비
- **대상 사용자**: 로그인 사용자 (`/mobile/*`)

  - **기본 틀**: 상단바 + 본문 + 하단 내비. 대상 — 홈, 나들이 목록, 여행 목록, 여행 상세, 달력(월/주), 신발 목록, 임장 전 화면(7개), 404

### COM-13 테마(화면 밝기) 선택
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 데스크톱 — 헤더 프로필 메뉴 내부. 모바일 — 마이페이지의 "화면" 영역
- **흐름**: 선택지 3개 중 하나를 선택 — "시스템" / "밝게" / "어둡게" (그룹 이름 "화면 밝기"). 선택 즉시 전체 화면에 반영.
- **상태**: 현재 선택값이 표시된다. 기본값은 "시스템".
- **결과/정책**:
  - "시스템"은 기기의 라이트/다크 설정을 따르고, 기기 설정이 바뀌면 즉시 따라 바뀐다. "밝게/어둡게"는 기기 설정과 무관하게 고정.
  - 선택은 이 브라우저에 저장되어 재방문 시 유지된다(계정에 저장되지 않음 — 기기·브라우저마다 별도). 저장소 사용이 불가한 환경에서는 그 세션 동안만 유지.
  - 모바일 브라우저 주소창 영역 색도 테마에 맞춰 바뀐다.
  - 로그인 화면에는 선택 UI가 없지만 저장된 테마/시스템 설정은 적용된다.
- **데스크톱/모바일 차이**: 진입 위치만 다름

### COM-14 로딩 · 빈 상태 · 에러 상태 공통 규칙
- **적용 범위**: 모든 목록/상세/폼 화면
- **규칙**:
  1. **로딩**: 내용이 들어올 자리를 대체하는 골격 표시(목록·상세 화면 다수) 또는 상태 알림 문구(예: 홈의 "일정을 불러오는 중"). 로딩 중에는 조작 대상 데이터 버튼을 노출하지 않는다.
  2. **빈 상태**: 제목(필수) + 설명(선택) + 이동 버튼(선택, 예: "첫 여행 기록하기")으로 구성. 데이터가 없는 이유와 다음 행동을 함께 안내한다.
  3. **에러 상태**: 제목(필수) + 설명(선택) + "다시 시도" 버튼(재시도 가능한 경우). "다시 시도" 는 실패한 요청만 다시 실행한다.
  4. 부분 실패(여러 데이터 중 일부만 실패)는 화면 전체를 에러로 바꾸지 않고 실패한 영역만 에러 문구와 "다시 시도" 로 표시한다(홈이 대표 사례).
  5. 서버 데이터 요청은 자동 재시도하지 않고(실패 즉시 에러 표시), 창 포커스 복귀 시 자동 갱신하지 않으며, 30초 동안은 같은 데이터를 신선한 것으로 취급해 재요청하지 않는다.
- **현재 공통 버튼 라벨**: "다시 시도"
- **데스크톱/모바일 차이**: 없음

### COM-15 파일 업로드 공통 규칙
- **대상 사용자**: 로그인 사용자 전체 (나들이 기록, 여행 등록, 임장 사진 등 업로드 화면)
- **흐름(파일 선택 영역)**: 1. 영역을 눌러 파일 선택 창을 열거나 파일을 끌어다 놓는다 2. 선택된 파일은 이미지면 미리보기 썸네일 + 파일 이름 + 크기(B/KB/MB 표기)로 표시 3. 지우기 버튼으로 선택 해제(단일은 해제 동작이 제공된 화면에서만 노출, 다중은 파일별 지우기)
- **입력 항목**: 라벨(필수 표시 `*` 가능), 안내 문구 기본값 "파일을 끌어다 놓거나 선택하세요", 힌트 기본값 "PNG · JPG · 최대 10MB" (화면별로 덮어씀), 오류 문구 영역.
- **상태**: 드래그 중 강조, 비활성, 오류(알림 역할의 오류 문구 + 입력 오류 표시).
- **정책·예외 규칙**:
  - 다중 선택 모드에서는 끌어다 놓은 파일이 기존 선택에 **추가**되고, 파일 선택 창에서 고르면 선택이 **교체**된다.
  - 서버 제한: 파일 1개당 최대 50MB, 한 요청 전체 110MB. 클라이언트는 사진을 최대 6장·합계 100MB 단위의 묶음으로 나누어 순서대로 올린다(한 파일을 쪼개지는 않음).
  - 업로드 실패 공통 문구(현재): 용량 초과(413) "사진 용량이 너무 커서 올리지 못했어요. 50MB 이하 사진으로 다시 시도해 주세요." / 네트워크 오류 "사진을 올리지 못했어요. 네트워크 연결을 확인해 주세요." / 서버 메시지가 있으면 "사진을 올리지 못했어요. {서버 메시지}"(HTML 응답이면 숨김) / 그 외 "사진을 올리지 못했어요. 잠시 뒤 다시 시도해 주세요."
  - 화면별로 안내 문구의 크기 제한(예: 나들이는 "10MB 이하")이 다를 수 있다 — 각 도메인 문서 참조.
  - 이미지 표시는 서버가 만드는 크기 변형(홈 대표/썸네일/원본 3종)만 사용하며, 이미지는 로그인 쿠키로 인증된다.
- **데스크톱/모바일 차이**: 없음

### COM-16 알림(토스트) 방식 및 오류 처리 방식
- **규칙**: 앱에는 **토스트(자동으로 사라지는 알림) 기능이 없다.** 결과 알림은 모두 해당 화면 안에 상주하는 문구로 표시된다 — 성공은 상태 알림(예: 프로필 저장 성공 배너), 실패는 오류 알림 영역(알림 역할)이며, 사용자가 입력을 바꾸면 사라지는 경우가 많다.
- **세션 만료 처리**: 인증 요청 헤더로 액세스 토큰을 보내며, **API 응답 401 을 전역에서 가로채 로그아웃/재로그인으로 보내는 로직은 없다.** 401 은 각 화면이 개별 처리한다(예: 나들이 저장 실패 문구 "로그인이 풀렸어요. 다시 로그인한 뒤 저장해 주세요."). 새로고침하면 COM-03 으로 세션이 다시 복원되거나 실패 시 로그인으로 이동한다.
- **서버 오류 메시지**: 서버가 주는 오류 제목(없으면 `상태코드 상태문구`)을 오류 메시지로 쓸 수 있으며, 화면별로 사용자 문구로 바꿔 보인다. 응답 형식이 계약과 다르면 "응답 형식 오류"로 취급해 일반 오류로 처리한다.
- **네트워크 오류**: 네트워크 실패는 별도 오류 종류로 구분되어 화면별로 "네트워크 연결을 확인해 주세요" 류 문구를 보인다.

## 기술 제약
- 인증: 로그인 응답으로 받은 토큰은 메모리에만 두고 요청 헤더로 전송, 세션 유지는 서버 쿠키(자격 증명 포함 요청)에 의존한다. 쿠키가 막히면 새로고침 시 로그아웃된다.
- 세션 저장소(탭 단위)에 사용자 정보가 저장되므로 탭을 닫으면 사라지고 다른 탭과 공유되지 않는다. 테마 선호는 브라우저 로컬 저장소(키 하나)에 저장.
- 기기 분기는 사용자 에이전트 문자열 기반이라 태블릿 일부·데스크톱 모바일 모드에서 의도와 다르게 분기될 수 있다.
- 지연 로딩: 화면 코드는 처음 열 때 내려받는다.
- 이미지 URL은 서버 규칙(`홈 대표 / 홈 썸네일 / 원본`)만 허용한다. 알 수 없는 변형 값은 서버가 조용히 다른 값으로 처리하므로 임의 값을 쓰면 안 된다.
- 업로드 서버 제한(위 COM-15). 오류 응답이 프록시의 HTML 일 수 있어 그 본문은 사용자에게 보여주지 않는다.
- `/stock` 은 같은 도메인의 별도 앱이라 전체 페이지 이동이 필요하다.
- 외부 링크: Choi's Film Art(`http://naver.me/52RjLNuT`)는 새 탭.

## 확인 필요
- 404 화면 문구에 서비스 이름이 포함되어 있고, 모바일 상단바 기본 제목·푸터 저작권 문구·로고 대체 텍스트·로그인 화면에 서비스 이름이 노출된다. 리디자인에서 이 위치에 어떤 이름을 쓸지 결정 필요(의미: 서비스 이름 표시).
- 관리자 전용 메뉴(임장 질문 관리)로 가는 전역 내비 진입점은 이 영역 코드에서 확인되지 않음(임장 문서에서 확인 필요). 일반 사용자 대상 숨김 여부도 임장 화면에서 확인 필요.
- 전역 401 처리 부재: 세션이 만료되어도 화면이 즉시 로그인으로 가지 않고 개별 오류로 표시됨. 의도된 동작인지 확인 필요.
- 데스크톱 홈 외 화면에서 신발 목록 진입점이 헤더 메뉴에 없음(홈 "더보기"에서만 진입). 의도 여부 확인 필요.
- 데스크톱 프로필 3개 경로(`/main/profile*`)는 홈으로 이동만 함. 기획상 별도 화면이 필요한지 확인 필요.
- 모바일 `/mobile/404` 가 기본 틀(하단 내비 포함)에서 열리는 반면 `/main/404` 는 데스크톱 틀에서 열림. 상세형 틀 하위 알 수 없는 경로는 404 로 이동.
- 토스트가 없어 일부 성공 피드백이 화면 이동으로만 전달되는 경우가 있는지(도메인별) 확인 필요.
