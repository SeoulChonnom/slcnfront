# Claude Design 전달용 기능 목록

브랜드·레이아웃·컴포넌트·CSS를 모두 새로 만드는 전면 리디자인에서 **기능이 하나도 빠지지 않게** 하기 위한 계약 문서다.

- Claude Design에 넘기는 입력 자료이며, 새 시안이 나오면 **누락 점검 체크리스트**로 쓴다.
- 리디자인 구현 전에 작성할 Playwright E2E 시나리오의 원천이기도 하다.

## 기준 시점

- 작성 기준: `feat/field-research-map` 브랜치 (커밋 `28707b5`). 2026-10-12에 작성했다.
- 이 문서는 main에 먼저 커밋되므로, **main에 아직 머지되지 않은 임장 기능도 포함**한다. 계획 임장, 매물 주소 검색·위치 저장, 매물 지도와 방문 순서, 도보 경로, 현재 위치 기준 추천 순서 등이 해당한다.
- 기능이 추가되거나 바뀌면 해당 영역 문서를 함께 고친다.

기능은 모두 131개다. 문서 하나가 800줄을 넘지 않도록 임장 영역은 여러 파일로 나눴다. 번호 사이의 빈 구간은 영역별 번호 대역으로 일부러 비워 둔 것이다.

각 영역 문서는 다음 순서로 구성된다.

1. 개요
2. URL
3. 기능 목록 (ID별: 대상 사용자, 진입 경로, 흐름, 입력, 표시 데이터, 상태, 결과, 정책, 기기 차이)
4. 데이터 필드 사전
5. 기술 제약
6. 확인 필요

## 작성 원칙

- **무엇을 할 수 있는지만 쓰고, 어떻게 생겼는지는 쓰지 않는다.**
  - 색, 폰트, 배치, 컴포넌트 이름, CSS 클래스는 새 디자인이 정할 몫이다.
  - 예외는 지도와 달력처럼 형태 자체가 기능인 경우다.
- **브랜드 중립**: 옛 서비스 이름을 쓰지 않고 "서비스"라고 쓴다.
- **사용자 문구는 "현재 문구"로 인용**한다. 표현은 바꿔도 되지만 의미는 보존해야 한다.
- **URL은 유지 대상**이다. 화면 구성은 자유롭게 바꿔도 되지만, 주소는 바꾸지 않는 것을 전제로 한다.
- 근거는 코드다. 코드로 확정하지 못한 것은 각 문서의 "확인 필요"에 모았다.

## Claude Design에 넘기는 방법

**함께 넘길 것**

- 이 폴더 전체
- 브랜드 중립으로 다시 쓴 제품 개요
- 새 브랜드 브리프

**넘기지 말 것**

- 기존 `DESIGN.md`
- 기존 프로토타입 HTML (`docs/` 아래)
- 기존 화면 캡처와 로고

새 디자인이 옛 디자인에 끌려가는 것을 막기 위해서다.

**요청문에 넣을 조건**

> 모든 기능 ID(예: `TRV-03`)가 새 구조의 어느 화면·요소에서 수행되는지 매핑표를 시안과 함께 제출하세요.
>
> 기능 ID 하나라도 매핑되지 않으면 시안을 확정하지 않습니다.
