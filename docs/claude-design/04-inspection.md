# 임장 (현장 조사)
## 개요
사용자는 부동산 임장(현장 조사)을 **지역 → 회차(방문) → 매물** 구조로 기록한다. 먼저 "임장 계획하기"로 지역과 예정일, 가볼 매물을 정해 두고(계획), 다녀온 뒤 회차 수정 화면에서 결과(재방문 의사·한줄평·장점/단점·사진)를 쓰고 매물별 문답을 채워 완료한다. 지역 상세에서는 회차별 기록, 매물 방문 순서(지도·도보 경로), 현재 위치 기준 추천 순서 정렬을 쓸 수 있다. 관리자는 매물마다 묻는 체크리스트 질문과 분류를 관리한다.

핵심 용어와 상태 모델:
- **지역**: 이름·설명을 가진 묶음. 회차를 여러 개 가진다.
- **회차(임장)**: 방문 일시를 가진 1회 기록. 서버 상태는 작성 중(DRAFT)/완료(COMPLETED) 두 가지이고, "최초 완료 시각"이 있으면 한 번이라도 완료된 적이 있는 것이다. 이 조합으로 화면에 **계획 / 수정 중 / 완료** 세 단계를 구분한다(INS-07).
- **매물**: 회차 안의 확인 대상. 단지/건물명(필수)과 동·호수(계획 단계에서는 비어도 됨)로 식별되며, 같은 지역 안에서 단지/건물명+동·호수가 같으면 회차 간 같은 매물로 묶어서 비교한다.
- **위치**: 매물에 저장하는 주소(도로명주소 검색 결과). 사용자 기기의 GPS는 쓰지 않는다.

## 기술 제약
- **지도**: 방문 순서·추천 미리보기의 배경 지도는 카카오맵 JavaScript SDK를 쓴다. 서비스에 지도 키가 설정되지 않았거나 SDK 로딩에 실패하면 지도는 표시되지 않고 번호 목록만 제공해야 한다(목록이 본체). 지도는 읽기 전용이며(좌표를 찍어 저장하는 기능 없음), 카카오 로고·저작권 표기를 가리거나 제거할 수 없고, 지도 하단에 "주소·좌표: 행정안전부" 출처 문구를 둔다. 지도 타일/데이터를 저장하거나 다른 지도로 대체 가공하는 것은 약관상 금지.
- **좌표·주소 출처**: 저장 가능한 좌표는 행정안전부 도로명주소 검색·좌표제공 결과뿐이다. 카카오/네이버 등 지도 사업자의 검색·지오코딩 결과 좌표는 DB에 저장할 수 없으므로 그 방식으로 위치 지정을 만들면 안 된다. FE는 좌표를 보내지 않고 건물관리번호(및 좌표 조회 키)만 보낸다. 건물이 같으면 기존 좌표를 유지하고 새 조회를 하지 않는다.
- **현재 위치**: 기기 GPS/브라우저 위치 권한은 쓰지 않는다. "현재 위치"는 사용자가 주소를 검색해 고른 값이며, 서버가 좌표 변환만 해 주고 어디에도 저장하지 않는다. 따라서 위치 권한 요청·거부 처리 화면은 존재하지 않는다. (GPS를 도입하면 위치정보 관련 법규 검토가 새로 필요하다.)
- **도보 경로**: 카카오 도보 경로를 사용자가 버튼을 누를 때만 서버를 통해 호출한다. 외부 유료 호출이며 하루 호출 한도(무료 1,000건 수준)가 있고 초과 시 안내 문구가 나온다. 결과는 저장·장기 캐시 금지로 화면 상태에만 보관하며, 순서나 주소가 바뀌면 폐기. 지도에는 서버가 준 경로 좌표를 그대로 그린다.
- **주소 검색**: 2자 이상, 입력 후 약 0.3초 뒤 조회, 같은 검색어는 1분 재사용. 서버 검색 기능이 꺼져 있으면(응답 503) 해당 입력이 비활성.
- **추천 순서 계산**: 브라우저에서 계산한다. 거리는 직선×1.3 보정(도보 실거리가 아님). 지점이 13곳을 넘으면 근사라 최적이 아닐 수 있다.
- **사진 업로드**: 파일당 최대 50MB(초과분은 건너뜀), 요청당 최대 6장·약 100MB로 나눠 순차 전송, 서버가 크기별 파생본을 만드는 동안 요청이 오래 걸릴 수 있어 진행 표시가 필요하다. 안내 형식은 JPG/PNG. 사진 URL은 크기 변형(썸네일/기능 사진)을 지정해서 요청해야 한다.
- **자동 저장**: 입력 후 2초 지연 저장, 화면 이탈 시 대기분 즉시 전송, 서버에 낙관적 잠금이 없어 동시 수정은 마지막 저장이 이김. 저장은 겹치지 않고 직렬 처리.
- **AI 초안**: 메모 최대 5,000자, 길면 약 30초 소요, 외부 서비스가 꺼져 있으면 서버 사유 문구가 반환될 수 있다. 서버는 초안을 저장하지 않는다.
- **시간대**: 회차 일시는 시간대 없는 지역 시각 문자열이며 브라우저 시간대 변환을 하면 안 된다.
- **서버 규칙**: 매물 수정은 전체 교체 방식이라 위치를 반드시 함께 보내야 한다. 질문 정책 수정은 순서값을 생략하면 0으로 초기화되므로 현재 순서값을 항상 함께 보낸다. 서버 오류는 코드로 분기한다(문구가 아니라 코드 기준).
- **접근성**: 회차 탭 키보드 조작(좌/우/Home/End), 재방문 의사·관심도·매물 상태는 색만으로 구분하지 않는다.
## 확인 필요
1. **위치 권한**: 요청사항에는 위치 권한 거부 처리가 있었으나 코드에는 브라우저 위치 API 사용이 전혀 없다(주소 입력 방식). 권한 거부 화면은 존재하지 않는 것으로 기록함.
2. **등록 3단계 진입 시점**: 2단계에서 "다음"을 눌러도 회차가 아직 저장되지 않았으면(자동 저장 약 2초 대기) 3단계 본문이 비어 보일 수 있다. 의도된 동작인지 불명.
3. **지역 상세의 "이 지역 다시 임장"**: 이동만 하고 지역이 미리 선택되지 않는다(1단계에서 다시 골라야 함). 기획상 사전 선택 의도 여부 불명.
4. **지역 목록 페이지 이동 없음**: 서버가 주는 한 페이지만 표시하고 "더 보기"/페이지 이동 동작이 없다. 지역이 많을 때와, "미정" 필터(화면 내 걸러내기)가 그 한 페이지에만 적용되는 한계가 있다.
5. **삭제 실패 안내 없음**: 회차 삭제(지역 상세·수정 화면), 매물 삭제(상세·편집)는 실패 시 사용자 안내 문구가 코드에 없다.
6. **문답 저장 실패 안내 없음**: 문답 자동 저장 실패 시 화면 문구가 없다.
7. **매물 상세에서 편집 진입 후 돌아가기**: 상세에서 연 편집도 `from=area`가 없어 완료·삭제 후 등록 마법사로 돌아간다(상세/지역 상세로 돌아가지 않음). 의도 여부 불명.
8. **주소 검색 일반 실패**: 키워드 거부와 서비스 꺼짐 외의 검색 실패는 문구 없이 목록이 비어 보인다.
9. **사진 순서 변경의 터치 대안 없음**: 끌어 놓기만 있고 위/아래 버튼 대안이 없다(매물 순서·질문 순서 이동에는 버튼이 있음).
10. **회차 수정의 필수 표시**: 임장 일시·재방문 의사에 필수 표시가 있으나 저장 시 클라이언트 검증이 없고, 일시가 비면 오류 안내 없이 저장을 건너뛴다. 완료 가능 여부는 서버 판단.
11. **지역 삭제**: 지역 삭제 API 연동 코드는 있으나 화면 진입점이 없다(미사용).
12. **출처 표기·승인**: 기획 문서상 행안부 출처 표시 문구, 트래픽 한도, 좌표 API 승인키가 미확정 항목으로 남아 있다. 현재 화면은 "주소·좌표: 행정안전부"만 표기. 도보 경로 응답을 세션 메모리에 보관해도 되는지도 기획 문서에서 미확인.
13. **지역 행의 최근 회차 배지**: 가장 최근 회차가 계획인지 여부는 서버 응답에 달려 있어 목록에서 "계획" 배지가 실제로 나타나는 경우를 코드만으로 확정하지 못함(예정 표시는 별도로 있음).
14. **기획 문서와의 차이**: 기획(D12)의 "빼고 완료하기" 기능은 미구현이며, 안 간 매물은 삭제 후 완료하는 방식이다. 계획 임장의 집계 제외 규칙은 서버 규칙에 의존.
