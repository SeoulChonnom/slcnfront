# 달력 (일정)

## 개요
사용자는 달력에서 월 단위 또는 주 단위로 일정을 조회하고, 일정을 등록·수정·삭제한다. 일정은 "캘린더"(일정 분류 단위, 사람/주제별 묶음)에 속하며, 캘린더마다 표시 색과 편집 권한이 있고 사용자가 캘린더 자체도 만들고 고치고 지울 수 있다. 캘린더 단위로 일정을 켜고 끌 수 있으며, 일정은 달력 위에서 끌어서 날짜/시간을 옮기거나 길이를 조절할 수도 있다. 홈 화면의 "다음 일정"과 연결된다.

## URL
| 경로 (/main, /mobile 공통 뒤쪽) | 화면 의미 | 접근 권한 | 비고 |
|---|---|---|---|
| `calendar` | 월 보기 | 로그인 사용자 전체 | 쿼리 `date=YYYY-MM-DD`로 기준일 지정. 없거나 형식이 잘못되면 오늘로 처리 |
| `calendar/week` | 주 보기 | 로그인 사용자 전체 | 쿼리 `date=YYYY-MM-DD`. 기준일이 속한 주(일요일 시작~토요일)를 보여줌 |

- 비로그인 접근 시 로그인 화면으로 이동한다(공통 인증 가드). 달력 전용 관리자 제한 경로는 없다.
- 기준일은 URL 쿼리에 담기므로 새로고침·공유·뒤로가기로 같은 기간이 복원된다.

## 기능 목록

### CAL-01 월 보기로 일정 조회
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 하단/상단 메뉴의 "달력", 홈의 "달력 보기" 링크 또는 "다음 일정" 항목 클릭(월 보기로 이동, 특정 일정/날짜로 포커스되지는 않음), 주 보기에서 "월" 전환
- **흐름**:
  1. 기준일이 속한 달 전체가 월 달력으로 표시된다(해당 달 주 수만큼만 행 표시, 6주 고정 아님). 요일 머리글/날짜 숫자는 한국어, 날짜 칸에는 숫자만 표시.
  2. 하루에 일정이 3개를 넘으면 3개까지만 보이고 나머지는 "더보기" 형태로 접힌다(FullCalendar 기본 동작).
  3. 일정은 소속 캘린더의 배경/테두리/글자 색으로 표시된다.
- **표시 데이터**: 기간 라벨(현재 문구 형식: "2026년 10월"), 일정 제목, 일정 색(캘린더 색), 종일/시간 일정 구분, 여러 날에 걸친 일정의 기간 막대
- **상태**:
  - 로딩: 달력 자리에 자리표시 2개(스켈레톤)
  - 에러: 현재 문구: "일정을 불러오지 못했어요." / 설명 "잠시 후 다시 시도하거나, 네트워크 상태를 확인해 주세요." / 다시 시도 동작 제공 (캘린더 목록 또는 일정 목록 둘 중 하나라도 실패하면 에러)
  - 빈 상태(캘린더 자체가 0개): 현재 문구: "캘린더가 아직 없어요." / "캘린더를 만들면 일정 화면에서 바로 추가하고 관리할 수 있어요."
  - 빈 상태(표시 중인 캘린더가 0개): 현재 문구: "표시 중인 캘린더가 없어요." / "상단 필터에서 하나 이상의 캘린더를 다시 켜주세요."
  - 일정이 없는 달은 달력만 비어 보이고 별도 안내 문구는 없음(데스크톱 기준)
- **결과**: 조회 전용 동작
- **정책·예외 규칙**: 조회 범위는 해당 달 1일 0시 ~ 다음 달 1일 0시. 범위와 겹치는 일정만 표시(전달에서 이어지는 일정 포함). 반복 일정은 서버가 기간 내 발생분으로 펼쳐서 내려준다.
- **데스크톱/모바일 차이**: 모바일은 월 달력 아래에 해당 달의 일정 목록(CAL-04)이 추가로 표시된다. 데스크톱은 달력만 표시.

### CAL-02 주 보기로 일정 조회
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 월 보기에서 "주" 전환
- **흐름**:
  1. 기준일이 속한 주(일~토) 7일이 시간 축과 함께 표시된다. 상단에 종일 일정 영역이 있고, 시간 일정은 오전 7시~오후 11시 구간으로 표시된다. 현재 시각 표시선이 있다.
  2. 일정은 캘린더 색으로 표시된다.
- **표시 데이터**: 기간 라벨(현재 문구 형식: 같은 달이면 "10월 11일 - 17일", 달이 걸치면 "9월 28일 - 10월 4일"), 일정 제목, 시작·종료 위치, 종일 여부
- **상태**: CAL-01과 동일한 로딩/에러/빈 상태(캘린더 없음, 표시 캘린더 없음)
- **결과**: 조회 전용
- **정책·예외 규칙**: 조회 범위는 주 시작일 0시 ~ 7일 후 0시. 07:00 이전/23:00 이후 시간대는 시간 축에 나타나지 않는다.
- **데스크톱/모바일 차이**: 모바일은 시간 축 달력 대신 "요일·날짜 7칸 띠 + 일자별 일정 목록"(CAL-04)으로 표시된다. 모바일 주 보기에서는 달력 위에서 직접 날짜/시간 구간을 선택해 일정을 만드는 동작, 끌어서 옮기기·길이 조절은 불가(목록 항목 탭 → 수정 화면, 상단 "일정 추가" 버튼만 가능).

### CAL-03 날짜 이동 (이전/다음/오늘)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 상단 도구줄의 이전 화살표(접근성 라벨 "이전 달"), "오늘" 버튼, 다음 화살표(접근성 라벨 "다음 달")
- **흐름**: 월 보기에서는 한 달씩, 주 보기에서는 한 주씩 이동(기준일을 ±1달/±1주). "오늘"은 오늘 날짜가 속한 기간으로 이동. 이동 시 URL의 `date`가 갱신되고 해당 기간을 새로 조회한다. 상단 제목에 현재 기간 라벨이 표시된다.
- **상태**: 이동 직후 새 기간 조회 동안 CAL-01의 로딩 상태가 보일 수 있음
- **결과**: 같은 보기(월/주)에서 기준일만 바뀜
- **정책·예외 규칙**: 이동 가능 범위에 제한 없음. 주 보기의 이전/다음 버튼 접근성 라벨도 "이전 달/다음 달"로 동일(주 보기에서 라벨 의미가 어긋남 → 확인 필요).
- **데스크톱/모바일 차이**: 없음

### CAL-04 모바일 일정 목록(아젠다) 보기
- **대상 사용자**: 로그인 사용자 전체 (모바일 화면)
- **진입 경로**: 모바일 월 보기(달력 아래), 모바일 주 보기(본문)
- **흐름**:
  1. 기간 내 날짜를 "M월 D일 (요일) 일정" 제목의 구역으로 나누어 보여준다. 일정이 있는 날만 구역이 생기며, 오늘은 일정이 없어도 항상 구역이 생긴다.
  2. 열릴 때와 기간이 바뀔 때 오늘 구역이 목록 맨 위에 오도록 스크롤된다(오늘이 기간 밖이면 해당 없음).
  3. 항목에는 시작 시각(예: "오후 2:30") 또는 "종일", 제목, 캘린더 색 표시가 있다. 항목을 탭하면 일정 수정 화면(CAL-07)이 열린다.
  4. 모바일 주 보기에는 목록 위에 일~토 7일 띠(요일, 날짜 숫자)가 있고 오늘이 강조된다. 띠 자체는 탭 동작 없음.
- **상태**:
  - 기간 내 일정이 하나도 없고 오늘도 기간 밖: 현재 문구: "이 기간에는 등록된 일정이 없어요."
  - 오늘 구역에 일정이 없을 때: 현재 문구: "오늘 등록된 일정이 없어요."
- **정책·예외 규칙**: 여러 날에 걸친 일정은 각 날짜 구역에 나타나며 첫날은 시작 시각, 이후 날짜는 "종일"로 표시. 정렬: 종일 먼저, 이후 시작 시각 순. 수정 불가 캘린더의 일정은 탭해도 아무 일도 일어나지 않는다.
- **데스크톱/모바일 차이**: 모바일 전용

### CAL-05 캘린더(분류)별 표시 켜기/끄기 필터
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 상단 도구줄의 "캘린더 필터" 줄에 캘린더별 칩(색 점 + 이름) 나열, 또는 "캘린더 관리"(CAL-10)의 표시 스위치(접근성 라벨 "{이름} 표시")
- **흐름**: 칩을 누를 때마다 해당 캘린더의 일정이 달력/목록에서 숨겨지거나 다시 나타난다. 처음에는 서비스에서 "표시 가능(visible)"으로 내려준 캘린더가 모두 켜져 있다.
- **상태**: 모든 캘린더를 끄면 CAL-01의 "표시 중인 캘린더가 없어요." 안내가 나온다.
- **정책·예외 규칙**: 선택 상태는 화면 안에서만 유지되며 다른 기간으로 이동해도 유지되지만 새로고침/다른 보기 전환(월↔주는 페이지 이동이므로 초기화될 수 있음)에서는 초기화됨 → 확인 필요. 서버가 visible=false로 내려준 캘린더는 필터 칩에도 나타나지 않는다.
- **데스크톱/모바일 차이**: 없음

### CAL-06 일정 등록
- **대상 사용자**: 로그인 사용자 전체 (단, "일정 추가·수정 가능" 캘린더가 하나라도 표시 중이어야 함. 별도 관리자 전용 제한은 없음)
- **진입 경로**: (a) 상단 "일정 추가" 버튼, (b) 달력의 빈 날짜/시간 칸 클릭, (c) 달력에서 날짜·시간 구간 드래그 선택 (모바일 주 보기 제외)
- **흐름**:
  1. 화면 이동 없이 일정 입력 단계(별도 단계)가 열린다. 제목은 "일정 추가". 제목 입력에 자동 포커스.
  2. 초기값: "일정 추가" 버튼은 현재 시각~1시간 뒤. 월 보기 날짜 클릭은 그 날 종일. 주 보기 시간칸 클릭은 클릭한 시각부터 1시간. 구간 선택은 선택한 구간(종일 영역 선택이면 종일). 캘린더는 표시 중인 편집 가능 캘린더 중 첫 번째가 기본 선택.
  3. 저장 → 닫히고 달력에 즉시 반영.
- **입력 항목**:

| 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
|---|---|---|---|---|
| 제목 | 텍스트 (placeholder "예) 부암동 나들이") | 필수 | 공백만 입력 불가. 저장 시 앞뒤 공백 제거 | "제목을 입력해 주세요." |
| 캘린더 | 단일 선택 (편집 가능한 캘린더만 후보, 색 점+이름) | 필수 | 편집 불가 캘린더로는 변경/저장 불가 | "캘린더를 선택해 주세요." / "선택한 캘린더에는 일정을 저장할 수 없어요." |
| 설명 | 여러 줄 텍스트 | 선택 | 저장 시 앞뒤 공백 제거 | - |
| 장소 | 텍스트 | 선택 | 저장 시 앞뒤 공백 제거 | - |
| 종일 일정 | 체크박스 | 선택 | 켜면 시작/종료 시각 입력이 사라짐 | - |
| 시작일 | 날짜 | 필수 | 유효한 날짜 | "일정 시간을 다시 확인해 주세요." |
| 시작 시각 | 시각 (종일이면 숨김) | 종일 아닐 때 필수 | 유효한 시각 | "일정 시간을 다시 확인해 주세요." |
| 종료일 | 날짜 | 필수 | 종일: 시작일보다 빠를 수 없음(같은 날 가능, 종료일 포함 방식 입력) | "종일 일정 종료일은 시작일보다 빠를 수 없어요." |
| 종료 시각 | 시각 (종일이면 숨김) | 종일 아닐 때 필수 | 시작(날짜+시각)보다 늦어야 함 | "종료 시각은 시작 시각보다 늦어야 해요." |

- **표시 데이터**: 위 입력 항목 + 서버 오류 메시지(있으면 그대로 표시, 없으면 기본 문구)
- **상태**: 처리 중에는 버튼/캘린더 선택 비활성 및 저장 버튼 로딩 표시. 에러는 입력 단계 안에 알림 형태로 표시되며 입력값은 유지된다. 현재 문구(저장 실패 기본): "일정을 저장하지 못했어요. 잠시 후 다시 시도해 주세요."
- **결과**: 성공 시 입력 단계가 닫히고 일정 목록/달력이 갱신된다. 취소 버튼 또는 닫기로 입력 취소(저장 확인 절차 없음, 입력 내용 버려짐).
- **정책·예외 규칙**:
  - "일정 추가" 버튼은 표시 중인 캘린더가 없거나 표시 중인 캘린더가 모두 편집 불가이면 비활성. 이때 날짜 클릭·구간 선택으로도 등록 불가.
  - 종일 일정은 저장 시 서버에 "종료일 다음 날"(배타 종료)로 전달되나 화면은 마지막 날 기준으로 입력/표시.
  - 입력 시각은 시차(UTC 오프셋) 포함 형식으로 전달된다.
  - 반복 일정을 새로 만드는 입력은 없다(반복 규칙 입력 UI 없음).
- **데스크톱/모바일 차이**: 모바일 주 보기에서는 (b)(c) 진입이 없음. 그 외 동일.

### CAL-07 일정 수정 (내용)
- **대상 사용자**: 로그인 사용자 전체 (소속 캘린더가 편집 가능일 때)
- **진입 경로**: 달력 위 일정 클릭/탭, 모바일 목록 항목 탭
- **흐름**: 입력 단계가 "일정 수정" 제목으로 기존 값이 채워져 열린다. 항목·검증은 CAL-06과 동일. 저장 시 기존 일정을 갱신한다.
- **상태 / 결과**: CAL-06과 동일. 현재 문구(저장 실패 기본): "일정을 저장하지 못했어요. 잠시 후 다시 시도해 주세요."
- **정책·예외 규칙**:
  - 소속 캘린더가 "일정 추가·수정" 불가이면 일정을 눌러도 아무 반응이 없다(조회 상세 화면 없음 → 읽기 전용 일정은 제목/색 외 내용을 볼 방법이 없음. 확인 필요).
  - 수정 화면에서 캘린더를 다른 편집 가능 캘린더로 옮길 수 있다.
  - 종일 일정의 종료일은 마지막 날 기준으로 표시된다.
  - 반복 일정은 CAL-09 참조.
- **데스크톱/모바일 차이**: 없음

### CAL-08 일정 날짜·시간 변경 (끌어서 옮기기 / 길이 조절)
- **대상 사용자**: 로그인 사용자 전체 (캘린더가 해당 권한을 가진 경우)
- **진입 경로**: 데스크톱 월/주 보기, 모바일 월 보기의 달력 위에서 일정 막대를 끌어 다른 날짜/시간에 놓기, 또는 막대 끝을 끌어 길이 조절
- **흐름**: 놓는 즉시(확인 절차 없이) 새 시작/종료로 서버에 저장하며 별도 입력 단계는 열리지 않는다.
- **상태**: 저장 실패 시 일정이 원래 위치로 되돌아간다(별도 에러 문구 없음). 저장 중 표시 없음.
- **정책·예외 규칙**:
  - 캘린더 권한이 3단계: "일정 추가·수정하기"(editable), "시작 시간 옮기기"(startEditable), "길이 조절하기"(durationEditable). 옮기기는 editable+startEditable, 길이 조절은 editable+durationEditable이 모두 켜져야 한다. 아니면 원위치.
  - 반복 일정은 끌 수 없다.
  - 종일 일정은 날짜 단위, 시간 일정은 시각 단위(주 보기)로 이동.
- **데스크톱/모바일 차이**: 모바일 주 보기에는 없음. 터치 기기의 끌기 동작 지원 여부는 확인 필요.

### CAL-09 반복 일정 조회·삭제 제한
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 서버가 반복 규칙을 가진 일정(이미 서버에 등록된 것)을 내려주면 달력에 발생 건마다 개별 항목으로 표시됨. 해당 항목 클릭
- **흐름**: 입력 단계 제목이 "반복 일정"이며 모든 입력이 읽기 전용이다. 안내 문구, 삭제 버튼, 취소 버튼만 있고 저장 버튼은 없다.
- **표시 데이터**: 일정 제목·캘린더·설명·장소·종일·시작/종료(읽기 전용), 안내
- **상태**: 현재 문구(안내): "반복 일정은 여기서 수정할 수 없어요. 삭제하면 반복되는 일정 전체가 함께 삭제돼요." / 저장 시도 방어 문구: "반복 일정은 여기서 수정할 수 없어요."
- **정책·예외 규칙**: 수정 불가 이유는 기술 제약(발생 건 하나가 시리즈 전체 시작일을 바꾸게 됨). 삭제는 시리즈 전체 삭제(CAL-11의 확인 문구가 반복용으로 바뀜). 끌어서 이동·길이 조절도 불가.
- **데스크톱/모바일 차이**: 없음

### CAL-10 캘린더(분류) 관리: 목록·표시 스위치·추가·수정·삭제
- **대상 사용자**: 로그인 사용자 전체 (관리자 구분 없음, 역할 검사 코드 없음 → 서버 권한 거부 시 오류 문구로만 드러남. 확인 필요)
- **진입 경로**: 도구줄의 "캘린더 관리" 버튼 (캘린더가 0개여도 사용 가능)
- **흐름**:
  1. 화면 이동 없이 "캘린더 관리" 단계가 열려 캘린더 목록(정렬 순서대로, 색 점+이름)이 나온다. 각 행은 (a) 이름을 눌러 수정으로 진입(접근성 라벨 "{이름} 편집"), (b) 표시 스위치(접근성 라벨 "{이름} 표시")를 가진다. 목록 끝에 "새 캘린더 추가".
  2. "새 캘린더 추가" 또는 이름 클릭 시 같은 단계 안에서 편집 양식("캘린더 만들기" / "캘린더 수정")으로 전환된다. "뒤로"로 목록 복귀(저장 안 하고 입력 버림).
  3. 저장 성공 시 목록으로 돌아가고 데이터가 갱신된다.
  4. 수정 중에는 "삭제" 버튼이 있다 → 확인 절차 → 삭제 성공 시 목록 복귀.
- **입력 항목**:

| 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
|---|---|---|---|---|
| 캘린더 이름 | 텍스트 (placeholder "예) 아영") | 필수 | 공백만 입력 불가 | "캘린더 이름을 입력해 주세요." |
| 배경 색상 | 색상 선택 + 색 코드 직접 입력 | 필수(기본값 분홍 계열 #fe9fc8) | 형식 검증 없음(서버 응답에 의존) | - |
| 테두리 색상 | 색상 선택 + 색 코드 직접 입력 | 필수(기본 #fe9fc8) | 동일 | - |
| 텍스트 색상 | 색상 선택 + 색 코드 직접 입력 | 필수(기본 #111111) | 동일 | - |
| 정렬 순서 | 숫자 (0 이상) | 필수 | 새 캘린더 기본값 = 기존 최대값+1 | "정렬 순서는 0 이상의 숫자로 입력해 주세요." |
| 일정 추가·수정하기 | 체크박스 (기본 켜짐) | 선택 | 끄면 아래 두 항목이 자동으로 꺼지고 비활성 | - |
| 시작 시간 옮기기 | 체크박스 (기본 켜짐) | 선택 | "일정 추가·수정하기"가 켜져 있을 때만 변경 가능 | - |
| 길이 조절하기 | 체크박스 (기본 켜짐) | 선택 | 위와 동일 | - |

- **표시 데이터**: 캘린더 목록(이름, 배경색, 표시 여부), 편집 양식 값
- **상태**:
  - 처리 중: 버튼 비활성, 저장 버튼 로딩
  - 에러: 서버 오류 메시지가 있으면 그대로, 없으면 현재 문구: "캘린더를 저장하지 못했어요. 잠시 후 다시 시도해 주세요." / 삭제 실패: "캘린더를 삭제하지 못했어요. 잠시 후 다시 시도해 주세요."
  - 목록이 비어 있으면 "새 캘린더 추가"만 보임(별도 빈 문구 없음)
  - 삭제 확인(별도 확인 절차): 제목 `"{이름}" 캘린더를 삭제할까요?` / 설명 "삭제한 캘린더는 되돌릴 수 없어요. 일정이 남아 있는 캘린더는 일정을 먼저 옮기거나 지워야 삭제할 수 있어요." / 버튼 "정말 삭제할게요" · "계속 둘게요"
- **결과**: 저장·삭제 후 캘린더·일정 데이터를 다시 불러와 필터/달력에 즉시 반영
- **정책·예외 규칙**: 서버 쪽에서 일정이 남은 캘린더 삭제를 거부할 수 있으며 그 오류 메시지가 그대로 노출될 수 있다. 목록의 "표시" 스위치는 CAL-05 필터와 같은 상태다. 서버가 visible=false로 내려준 캘린더는 이 목록에도 안 나온다(화면에서 visible 값을 바꾸는 입력도 없음).
- **데스크톱/모바일 차이**: 없음

### CAL-11 일정 삭제
- **대상 사용자**: 로그인 사용자 전체 (일정 수정 화면에 진입 가능한 경우)
- **진입 경로**: 일정 수정 화면(CAL-07)/반복 일정 화면(CAL-09)의 "삭제" 버튼 (새 일정 입력 중에는 삭제 버튼 없음)
- **흐름**: "삭제" → 확인 절차 → 확정 시 삭제 후 닫힘.
- **상태**: 확인 문구 현재 문구: 제목 "일정을 삭제할까요?" / 설명 `"{일정 제목}" 일정이 사라지고, 다시 볼 수 없어요.` (제목이 비어 있으면 "이 일정"으로 대체) / 반복 일정은 `반복되는 "{제목}" 일정이 모두 사라지고, 다시 볼 수 없어요.` / 버튼 "삭제할게요" · "계속 둘게요". 처리 중 버튼 비활성. 실패 시 입력 단계에 서버 메시지 또는 현재 문구: "일정을 삭제하지 못했어요. 잠시 후 다시 시도해 주세요."
- **결과**: 달력/목록에서 즉시 제거. 반복 일정이면 모든 발생 건 제거.
- **데스크톱/모바일 차이**: 없음

### CAL-12 홈 "다음 일정"과의 연결
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 홈 화면의 "다음 일정" 구역 (제목 링크 "달력 보기", 각 일정 항목)
- **흐름**: 홈이 "현재 시점 이후 일정" 조회로 가장 가까운 일정 최대 3개를 보여주고, 항목/링크를 누르면 달력 월 보기(오늘 기준 달)로 이동한다.
- **표시 데이터**: 일정 시각(또는 "일정"), 제목, 장소(있을 때)
- **상태**: 로딩 "일정을 불러오는 중", 에러 "일정 정보를 불러오지 못했어요." (홈 소유 문구)
- **정책·예외 규칙**: 일정 시작일/해당 항목으로 달력이 포커스되지 않는다(기준일 미전달). 여행·나들이·임장 영역 데이터와 달력 일정 사이에 자동 연동(여행 등록 시 일정 생성, 일정에서 여행 링크 등)은 **없다**. 달력 일정은 독립 데이터이며 위치(장소)는 자유 텍스트다.
- **데스크톱/모바일 차이**: 없음

| 종일 여부 | 종일 일정 | true/false | 아니오 |
| 캘린더 id | 캘린더 식별자 | 문자열 | 아니오 |

| editable / startEditable / durationEditable | 일정 추가·수정 / 옮기기 / 길이 조절 권한 | true/false | 아니오 |
| sortOrder | 캘린더 정렬 순서 | 숫자 (오름차순) | 아니오 |

## 기술 제약
- 월/주 달력은 FullCalendar(한국어 로케일) 라이브러리가 그린다. 월 보기(날짜 격자)와 주 보기(시간 격자)로 구성되며, 날짜 클릭·구간 드래그 선택·일정 끌기·길이 조절은 이 라이브러리의 상호작용 기능에 의존한다. 이전/다음/오늘/월·주 전환은 라이브러리 기본 툴바를 쓰지 않고 별도 컨트롤로 제공한다(디자인은 이 컨트롤을 자유롭게 바꿀 수 있으나 같은 기능 필요).
- 일정 막대의 색은 일정 소속 캘린더의 배경색으로 칠해진다. 캘린더별 색은 사용자가 직접 지정하는 데이터이므로, 임의의 색 위에서도 글자가 읽히도록 테두리/글자색을 같이 쓴다(디자인 시스템의 고정 팔레트로 대체하면 캘린더 색 구분 기능이 사라진다).
- 월 보기 하루 칸에 일정이 3개를 넘으면 접힌다. 6주 고정이 아닌 가변 주 수.
- 주 보기 시간 범위는 07:00~23:00. 종일 영역 별도. 시계 기준 현재 시각 선이 표시된다.
- 주 시작은 일요일. 기간 조회 범위는 월(1일~다음 달 1일) / 주(일요일~다음 일요일).
- 종일 일정 종료일 규칙: 서버·FullCalendar는 배타 종료(마지막 날의 다음 날)를 쓰고 입력 양식은 마지막 날을 보여준다.
- 반복 일정은 서버에서 발생 건으로 펼쳐져 내려오며 개별 발생 건 수정은 불가(시리즈 시작일이 바뀌는 문제). 반복 규칙을 만드는 UI도 없다.
- 일정 시간은 UTC 오프셋 포함 형식으로 서버에 전달한다. 시간 입력은 브라우저 기본 날짜/시각 입력 컨트롤(HTML date/time/color 입력)에 의존한다.
- 일정 조회는 기간 단위로 호출하며 기간이 바뀔 때마다 재조회한다. 날짜 이동 시 달력은 새로 그려진다.
- 모바일 주 보기는 FullCalendar를 쓰지 않고 목록으로 대체되어 격자 기반 상호작용이 없다.
- 로그인(토큰) 필요. 홈 "다음 일정"은 별도의 "현재 이후 일정" 조회 API를 사용한다.

## 확인 필요
- 일정/캘린더 관리가 "관리자 전용"인지: 화면 코드에는 역할(관리자) 검사가 없다. 서버가 거부하면 오류 메시지만 노출된다. 실제 정책은 서버 확인 필요.
- 편집 불가(editable=false) 캘린더의 일정은 클릭해도 아무 반응이 없어 내용(설명·장소 등)을 확인할 방법이 없다. 읽기 전용 상세가 필요한지 기획 확인.
- 캘린더 필터 선택 상태가 월↔주 전환(페이지 전환) 시 유지되는지는 코드상 컴포넌트가 새로 만들어져 초기화될 가능성이 높음. 실제 동작 확인 필요.
- 이전/다음 버튼의 접근성 라벨이 주 보기에서도 "이전 달/다음 달"인 점.
- 터치 기기에서 일정 끌어서 옮기기/길이 조절/구간 선택이 동작하는지(모바일 월 보기).
- 홈에서 일정 항목을 눌러도 해당 날짜로 이동하지 않고 오늘 기준 월 보기로만 이동하는 것이 의도인지.
- 모바일 상단 제목은 "서비스명 + 달력" 형태의 문구가 쓰인다(서비스명 표기는 이 문서에서 생략).
- 여행·나들이·임장 영역과의 연동이 코드에 전혀 없음(일정 ↔ 해당 기록 연결은 미구현 또는 기획 없음).
- 일정 항목의 서버 오류 메시지 노출 형태(영문일 수 있음) 확인 필요.
