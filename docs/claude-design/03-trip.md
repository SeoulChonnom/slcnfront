# 나들이

## 개요
로그인 사용자는 다녀온 나들이 기록을 목록에서 찾아보고, 각 기록에 걸린 퀴즈를 맞히면 해당 나들이의 지도 상세 화면으로 들어간다. 상세 화면에서는 나들이 경로 지도(최대 2장)를 보고, 사진이 모인 외부 드라이브 링크를 연다. 관리자는 새 나들이를 3단계(기본 정보, 지도 정보, 퀴즈 정보)로 등록한다. 나들이 영역은 지도 SDK·경로 계산·주소 검색 같은 위치 기능을 쓰지 않고, 업로드된 지도 이미지를 보여 주는 방식이다.

## URL
| 경로 (/main, /mobile 공통 뒤쪽) | 화면 의미 | 접근 권한 | 비고 |
|---|---|---|---|
| map | 나들이 기록 목록 + 퀴즈 풀기 | 로그인 사용자 | 목록 화면 안에서 퀴즈를 처리(화면 이동 없음) |
| map/register | 새 나들이 등록(3단계) | 로그인 사용자가 접근 가능. 화면 진입 경로(등록 버튼)만 관리자에게 노출 | 경로 자체에는 관리자 제한이 없음. 최종 저장 권한은 서버가 판정(403 안내 문구 있음). "확인 필요" 참조 |
| map/:id | 나들이 상세(지도·드라이브 링크) | 로그인 사용자 | 퀴즈 통과 여부를 화면이 검사하지 않음. 주소로 직접 진입해도 열림 |

- 모든 경로는 로그인이 필요하며, 비로그인 상태에서는 로그인 화면으로 이동한다.
- 상단 내비게이션의 "나들이" 항목이 목록으로 연결된다.

## 기능 목록

### TRP-01 나들이 목록 보기
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 내비게이션 "나들이", 등록 완료 후 자동 이동, 등록 화면의 취소
- **흐름**: 1. 화면 진입 시 전체 나들이 기록을 불러온다. 2. 최신/정렬 기준 변경 수단은 없고, 서버가 준 순서 그대로 보여 준다. 3. 각 기록에서 "퀴즈 풀기"로 퀴즈를 시작한다(TRP-03).
- **표시 데이터**: 화면 제목 "[서비스명] 나들이 기록"(현재 문구, 서비스명 포함이므로 리디자인 시 서비스 중립 제목으로 교체 가능), 기록별 로고 이미지(썸네일), 날짜(YYYY.MM.DD 형식으로 표시), 유형 배지(AYO/RYU 원문 코드), 나들이 이름, 설명(있을 때만), 퀴즈로 잠겨 있다는 표시("퀴즈"), "퀴즈 풀기" 동작
- **상태**:
  - 로딩: 기록 3개 분량의 자리 표시(접근성 상 상태 안내 "loading")
  - 에러: 제목 "나들이 기록을 불러오지 못했어요." / 설명 "잠시 후 다시 시도해 주세요." + 다시 시도 동작
  - 빈 상태: 제목 "아직 남긴 나들이가 없어요." / 설명 "다녀온 기록을 적어 두면 다시 꺼내 볼 수 있어요." (관리자에게만 "새 나들이 기록하기" 동작 노출)
  - 로고 이미지가 없을 때: 대체 아이콘(장소 핀)
- **결과**: 없음(조회)
- **정책·예외 규칙**: 모든 기록이 퀴즈 잠금 상태로 표시된다(통과 이력을 기억하지 않음. 매번 퀴즈를 풀어야 상세로 이동). 날짜 표시는 서버 날짜가 `YYYY-MM-DD` 또는 `YYYYMMDD`일 때 점(.) 구분으로 변환.
- **데스크톱/모바일 차이**: 없음(같은 화면 기능)

### TRP-02 나들이 검색(필터)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 목록 상단 검색 입력
- **흐름**: 1. 검색어 입력. 2. 입력 즉시 목록이 걸러진다(서버 재요청 없음, 이미 불러온 목록 안에서 필터). 3. 검색어를 지우면 전체 복귀.
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 검색어 | 자유 텍스트 | 아니오 | 앞뒤 공백 무시, 대소문자 무시. 나들이 이름·표시 날짜(점 구분 형식)·유형 코드(AYO/RYU)를 합친 문자열에 포함되는지로 판정 | 없음 |
- **표시 데이터**: 입력란 안내 문구 "날짜 · 나들이 이름 · 유형으로 검색"
- **상태**:
  - 검색 결과 없음(전체 기록은 있으나 일치 0건): 제목 "검색 결과가 없어요" / 설명 "“{검색어}” 와 맞는 나들이를 찾지 못했어요."
  - 전체 기록 자체가 없으면 검색 결과 없음이 아니라 TRP-01의 빈 상태가 보인다.
- **결과**: 목록 즉시 갱신
- **정책·예외 규칙**: 유형은 화면에서 한글(아영/일권)이 아닌 코드(AYO/RYU)로 검색된다. 즉 "아영"으로 검색하면 일치하지 않는다. 페이지 이동·무한 스크롤은 없다.
- **데스크톱/모바일 차이**: 없음

### TRP-03 퀴즈 풀기(상세 잠금 해제)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 목록의 기록에서 "퀴즈 풀기"
- **흐름**:
  1. "퀴즈 풀기" → 해당 기록의 퀴즈를 서버에서 불러온다. 화면 이동 없이 목록 위의 별도 단계(현재는 대화창 형태)로 열린다. 제목은 나들이 이름, 부제는 `날짜 · 맞히면 지도가 열려요`.
  2. 퀴즈 문제(제목)와 보기 목록이 나타난다. 보기는 열 때마다(그리고 "다시 풀어보기"로 다시 불러올 때마다) 순서가 무작위로 섞인다. 첫 번째 보기에 포커스가 간다.
  3. 보기 하나를 고르면 즉시 정답 여부를 서버에 확인한다(별도 제출 버튼 없음. 선택 = 제출). 확인 중에는 보기 선택이 비활성화된다.
  4. 결과 안내가 나타난다(정답/오답 각각 TRP-04, TRP-05).
  5. 대화창은 닫기 동작(닫기 버튼 / ESC / 바깥 영역 클릭)으로 언제든 닫을 수 있고, 닫으면 진행 중이던 요청 결과는 무시된다.
- **표시 데이터**: 나들이 이름, 날짜, 안내 "맞히면 지도가 열려요"(결과가 나온 뒤에는 이 안내 제거), 퀴즈 문제 제목, 보기 텍스트 목록(2개 이상), 잠금 상태 표시(잠김/열림)
- **상태**:
  - 로딩: "퀴즈를 불러오는 중…"
  - 퀴즈 불러오기 실패: "퀴즈를 불러오지 못했어요. 잠시 후 다시 시도해 주세요." + "다시 시도하기"(퀴즈를 다시 불러옴)
  - 정답 확인 요청 실패: "답변을 확인하지 못했어요. 잠시 후 다시 시도해 주세요." + "다시 시도하기"(퀴즈를 처음부터 다시 불러옴. 선택했던 보기는 유지되지 않음)
  - 처리 중: 보기 전체 비활성화
- **결과**: 정답이면 TRP-04, 오답이면 TRP-05
- **정책·예외 규칙**: 정답 판정은 서버가 한다(화면에는 정답 보기가 내려오지 않음). 시도 횟수 제한·잠금 시간·점수 기록은 없고 무제한 재시도 가능. 다른 기록의 퀴즈를 열면 이전 퀴즈 상태는 초기화된다. 퀴즈 응답에서 문제 제목이 비어 있으면 문제 문구 없이 보기만 표시된다.
- **데스크톱/모바일 차이**: 없음

### TRP-04 정답 처리(지도 열기)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: TRP-03에서 정답 보기 선택
- **흐름**: 1. 열린 자물쇠 표시와 함께 "그날 남겨 둔 말" 라벨, 서버가 내려준 정답 제목, 정답 본문(관리자가 등록 시 입력한 정답 제목·정답 텍스트)이 표시된다. 2. "지도 보러가기"를 누르면 해당 나들이 상세(map/:id)로 이동하고 퀴즈 단계는 닫힌다.
- **표시 데이터**: 정답 제목, 정답 텍스트, 상태 라벨 "그날 남겨 둔 말"
- **상태**: 정답 안내는 상태 알림(자동 낭독) 역할. 포커스는 "지도 보러가기"에 위치.
- **결과**: 상세 화면으로 이동. 닫기/ESC로 닫으면 이동 없이 목록에 남는다(이동하려면 다시 풀어야 함).
- **정책·예외 규칙**: 정답 확인 후에도 서버에 "해제됨" 기록을 남기지 않으므로 상세 화면은 퀴즈 없이 다시 열 수 있다.
- **데스크톱/모바일 차이**: 없음

### TRP-05 오답 처리(잠금 유지)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: TRP-03에서 오답 보기 선택
- **흐름**: 1. 닫힌 자물쇠 표시와 함께 "아직 잠겨 있어요" 라벨, 오답 제목, 오답 본문(관리자가 등록한 오답 제목·텍스트)이 표시된다. 2. "다시 풀어보기" → 같은 퀴즈를 다시 불러와 보기 순서를 다시 섞어 TRP-03 2단계로 복귀. 3. "목록으로 돌아가기" → 퀴즈 단계를 닫고 목록에 머문다.
- **표시 데이터**: 오답 제목, 오답 텍스트, 상태 라벨 "아직 잠겨 있어요"
- **상태**: 포커스는 "다시 풀어보기"에 위치.
- **결과**: 지도 상세로 이동하지 않음
- **정책·예외 규칙**: 오답 횟수 제한 없음.
- **데스크톱/모바일 차이**: 없음

### TRP-06 나들이 상세 보기(지도)
- **대상 사용자**: 로그인 사용자 전체(퀴즈 통과를 화면이 강제하지 않음)
- **진입 경로**: 퀴즈 정답 후 "지도 보러가기", 또는 주소 직접 입력
- **흐름**: 1. 화면 진입 시 나들이 상세를 불러온다. 2. 나들이 경로 지도 이미지를 크게 보여 준다(첫 번째 지도가 기본). 3. 두 번째 지도가 있으면 지도 전환 선택이 나타나 지도 간 전환(TRP-07). 4. 드라이브 링크 영역(TRP-08).
- **표시 데이터**: 화면 제목 "[서비스명] 나들이 경로"(현재 문구), 지도 이미지(원본 크기, 첫 번째 지도 필수, 두 번째 지도 선택), 지도 전환 라벨 2개(있을 때), 드라이브 안내 영역. 상세 응답에는 나들이 이름·날짜·유형·로고도 포함되지만 현재 화면에는 표시하지 않는다.
- **상태**:
  - 로딩: 지도 자리 표시
  - 상세 조회 실패(없는 id 포함): 제목 "나들이 상세를 불러오지 못했어요." / 설명 "상세 경로 또는 파일 경로를 다시 확인해 주세요." + 다시 시도 동작
  - 지도 이미지 로딩 실패: 제목 "지도를 불러오지 못했어요." / 설명 "파일 경로를 다시 확인해 주세요."(지도 영역 안에 표시. 다른 지도로 전환하면 정상 지도가 다시 보일 수 있음)
- **결과**: 없음(조회). 목록으로 돌아가는 수단은 내비게이션/모바일 상단 뒤로가기에 의존(화면 자체에 "목록" 버튼 없음).
- **정책·예외 규칙**: 지도는 확대·이동 같은 지도 SDK 기능이 아니라 이미지 한 장이다(브라우저/OS 기본 확대만 가능). 이미지는 인증 쿠키로 서버에서 직접 로드된다.
- **데스크톱/모바일 차이**: 모바일은 상세 화면이 별도 하위 화면 틀(상세용 상단 구조)로 열린다. 기능은 동일.

### TRP-07 지도 전환
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 상세 화면 상단의 지도 전환 선택(두 번째 지도가 있는 나들이만)
- **흐름**: 1. 두 개 중 하나 선택. 2. 선택한 지도로 표시가 바뀐다. 기본값은 첫 번째.
- **표시 데이터**: 전환 라벨 2개. 라벨은 관리자가 등록한 "버튼 1"(첫 번째 지도용), "버튼 2"(두 번째 지도용) 텍스트이고, 비어 있으면 "첫 번째 지도", "두 번째 지도"로 대체.
- **상태**: 두 번째 지도가 없으면 전환 선택 자체가 표시되지 않는다.
- **결과**: 지도 이미지 교체. 지도 이미지 실패 상태는 지도별로 판단.
- **정책·예외 규칙**: 서버 필드명상 nextButtonText = 첫 번째 지도 라벨, previousButtonText = 두 번째 지도 라벨로 쓰인다(이름이 반대로 보이니 라벨 의미는 "버튼 1/2"로 이해).
- **데스크톱/모바일 차이**: 없음

### TRP-08 사진 드라이브 열기
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 상세 화면 하단 "사진은 드라이브에서 보기" 영역의 "드라이브 링크"
- **흐름**: 1. 동작 선택. 2. 관리자가 등록한 드라이브 주소가 새 탭으로 열린다(출처·창 연결 정보 차단 상태로).
- **표시 데이터**: 제목 "사진은 드라이브에서 보기", 안내 "암호 🔒 : 입사일", 동작 라벨 "드라이브 링크"
- **상태**: 링크 값이 없는 경우의 별도 처리는 없음(등록 시 필수이므로 정상 데이터에서는 항상 있음). 주소 형식 검증도 화면에서는 하지 않는다.
- **결과**: 새 탭에서 외부 드라이브가 열림. 서비스 내부에 사진 갤러리는 없음.
- **정책·예외 규칙**: 드라이브 비밀번호는 입사일이라는 안내만 표시되고 실제 값은 제공하지 않는다.
- **데스크톱/모바일 차이**: 없음

### TRP-09 새 나들이 등록 진입 (관리자 전용 진입점)
- **대상 사용자**: 관리자만 (진입 버튼 노출 기준)
- **진입 경로**: 목록 상단 "새 나들이 기록하기" 버튼, 또는 목록이 비어 있을 때의 같은 이름 동작
- **흐름**: 1. 동작 선택 → map/register로 이동.
- **상태**: 관리자 역할이 아니면 두 진입점 모두 보이지 않는다.
- **결과**: 등록 화면(TRP-10) 표시
- **정책·예외 규칙**: 관리자 판정은 로그인 사용자의 역할 목록에 "admin"이 있는지로 한다. 경로 자체는 일반 사용자도 주소로 열 수 있다("확인 필요").
- **데스크톱/모바일 차이**: 없음

### TRP-10 나들이 등록: 단계 진행·취소·임시저장 (공통 틀)
- **대상 사용자**: 관리자만 (저장 권한은 서버가 판정)
- **진입 경로**: TRP-09
- **흐름**:
  1. 3단계 마법사: 1 "기본 정보" → 2 "지도 정보" → 3 "퀴즈 정보". 상단에 단계 표시("나들이 등록 단계"; 각 단계의 상태는 완료/진행 중/예정으로 안내).
  2. 1·2단계에서 "다음": 해당 단계 입력을 검증하고, 통과해야 다음 단계로 이동. 실패하면 이동하지 않고 오류 표시 + 첫 번째 오류 항목에 포커스.
  3. 2·3단계에서 "이전": 오류 표시를 지우고 바로 이전 단계로 이동(검증 없음, 입력값 유지).
  4. 3단계에서 "저장": 3단계를 검증하고 통과하면 저장(TRP-14). 1단계에서 "이전"은 없다.
  5. "취소": 입력한 내용이 하나라도 있으면 확인 절차(별도 단계)가 뜨고, 없으면 바로 목록으로 이동.
  6. 단계가 바뀌면 화면이 맨 위로 이동한다(동작 줄이기 설정 시 애니메이션 없이).
- **표시 데이터**: 화면 제목 "새 나들이 기록하기"(데스크톱에서만 시각 노출. 모바일은 화면 낭독용으로만 존재), 단계 목록, 하단 동작 줄("취소", "이전", "다음"/"저장")
- **상태**:
  - 임시저장 복원: 이전에 작성하다 나간 내용이 있으면 진입 시 자동 복원하고 안내 "작성하던 내용을 불러왔어요." (파일을 골랐던 항목이 있으면 이어서 " 로고 이미지 · 지도 1 · 지도 2 파일은 다시 선택해 주세요." 형태로 다시 선택해야 할 파일 이름을 나열). 복원 시 항상 1단계에서 시작.
    - "이어서 쓰기": 안내만 닫는다(내용 유지).
    - "새로 쓰기": 임시저장을 지우고 모든 입력을 초기화한 뒤 1단계로.
  - 이탈 확인(취소): 제목 "작성을 그만둘까요?" / 설명 "지금까지 고른 파일은 사라져요. 적어 둔 글은 이 브라우저에 남아 있어서 다시 들어오면 이어서 쓸 수 있어요." / 버튼 "나가기"(목록으로 이동), "계속 쓸게요"(머무름)
  - 입력이 있는 상태에서 새로고침·탭 닫기: 브라우저 기본 이탈 경고가 뜬다.
  - 저장 중: "저장" 버튼이 처리 중 상태(중복 저장 방지)
- **결과**: 저장 성공 시 목록으로 이동(TRP-14)
- **정책·예외 규칙**:
  - 임시저장은 브라우저 탭 세션 저장소에 입력 글자만 보관한다(탭을 닫으면 사라짐). 선택한 이미지 파일 자체는 저장되지 않는다.
  - 입력이 "있음"의 기준: 초기 상태(모든 항목 비어 있고 보기 3칸이 모두 빈 값)와 다르면 입력 있음. 파일 선택 여부 포함.
  - 값이 초기 상태인 동안은 임시저장을 만들지 않는다.
  - 저장 성공 시 임시저장 삭제.
- **데스크톱/모바일 차이**: 제목 노출만 다름(데스크톱 노출, 모바일 숨김). 모바일은 하위 화면 틀 안에서 열린다.

### TRP-11 등록 1단계: 기본 정보
- **대상 사용자**: 관리자만
- **진입 경로**: 등록 화면 시작 / 이전 단계에서 복귀
- **흐름**: 입력 후 "다음" → 검증 통과 시 2단계.
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 유형 | 단일 선택 "아영"(값 AYO) / "일권"(값 RYU) | 예 | 둘 중 하나여야 함. 기본 선택 없음 | 유형을 선택해 주세요. |
  | 날짜 | 날짜 선택(년-월-일) | 예 | 비어 있지 않을 것. 범위 제한 없음(미래 날짜 허용) | 날짜를 입력해 주세요. |
  | 나들이 이름 | 텍스트 | 예 | 공백만 입력 불가. 안내 예시 "예) 부암동 나들이". 길이 제한 없음 | 나들이 이름을 입력해 주세요. |
  | 로고 이미지 | 이미지 파일 1개(끌어다 놓기 또는 선택) | 예 | 확장자 jpg/jpeg/png/gif/svg 이면서 형식(MIME)도 image/jpeg·png·gif·svg+xml 일 것, 10MB 이하. 안내 "PNG · JPG · GIF · SVG · 최대 10MB". 선택 후 해제 가능 | 파일 미선택: 파일을 선택해 주세요. / 형식 불일치: 허용되지 않은 파일 형식입니다. 이미지 파일만 업로드해 주세요. / 초과: 파일 크기는 10MB를 초과할 수 없습니다. |
- **표시 데이터**: 선택한 파일 표시와 해제 동작, 파일 안내 문구 "로고 파일을 끌어다 놓거나 선택하세요"
- **상태**: 검증 실패 시 위 순서(유형, 날짜, 이름, 로고)대로 첫 오류 항목에 포커스. 항목을 수정하면 해당 오류가 즉시 사라진다.
- **결과**: 2단계로 이동
- **정책·예외 규칙**: 오류는 "다음" 시점에만 검사(입력 중 실시간 검사 없음).
- **데스크톱/모바일 차이**: 없음

### TRP-12 등록 2단계: 지도 정보
- **대상 사용자**: 관리자만
- **진입 경로**: 1단계 "다음"
- **흐름**: 1. 지도 1 파일 선택. 2. 필요하면 "2번 지도 추가하기"로 두 번째 지도 입력 영역을 연다(다시 누르면 "2번 지도 지우기"). 3. 드라이브 링크 입력. 4. "다음" → 검증 통과 시 3단계.
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 지도 1 | 이미지 파일 | 예 | 로고와 동일(형식·10MB). 안내 "지도 1 파일을 끌어다 놓거나 선택하세요" | 파일을 선택해 주세요. / 허용되지 않은 파일 형식입니다. 이미지 파일만 업로드해 주세요. / 파일 크기는 10MB를 초과할 수 없습니다. |
  | 2번 지도 사용 여부 | 토글 동작 "2번 지도 추가하기" ↔ "2번 지도 지우기" | 아니오 | 끄면 지도 2와 버튼 1·2 입력값이 모두 지워짐 | 없음 |
  | 지도 2 | 이미지 파일 | 2번 지도 사용 시 예 | 지도 1과 동일 규칙 | 지도 1과 동일 문구 |
  | 버튼 1 | 텍스트 | 2번 지도 사용 시 예 | 공백만 불가. 안내 "상세 화면에서 지도 1을 여는 탭 이름이 돼요." | 첫 번째 버튼 라벨을 입력해 주세요. |
  | 버튼 2 | 텍스트 | 2번 지도 사용 시 예 | 공백만 불가. 안내 "상세 화면에서 지도 2를 여는 탭 이름이 돼요." | 두 번째 버튼 라벨을 입력해 주세요. |
  | 드라이브 링크 | 텍스트(주소) | 예 | 공백만 불가. URL 형식 검증 없음 | 드라이브 링크를 입력해 주세요. |
- **표시 데이터**: 안내 "드라이브 비밀번호는 상세 화면에서 입사일로 안내됩니다."
- **상태**: 검증 실패 시 포커스 순서: 지도 1 → (2번 지도 사용 시) 지도 2 → 버튼 1 → 버튼 2 → 드라이브 링크.
- **결과**: 3단계로 이동
- **정책·예외 규칙**: 지도는 최대 2장. 2번 지도를 쓰지 않으면 버튼 라벨은 서버에 전송되지 않는다. 지도 2 없이 버튼만 있는 상태는 불가.
- **데스크톱/모바일 차이**: 없음

### TRP-13 등록 3단계: 퀴즈 정보
- **대상 사용자**: 관리자만
- **진입 경로**: 2단계 "다음"
- **흐름**: 1. 퀴즈 제목, 보기(최소 3개 ~ 최대 6개), 정답 번호, 정답/오답 안내문 입력. 2. "보기 추가"로 보기를 늘리고, 4번째 이후 보기는 개별 "삭제" 가능(보기 1~3은 삭제 불가). 3. 정답 번호 선택. 4. "저장".
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 퀴즈 제목 | 텍스트 | 예 | 공백만 불가 | 퀴즈 제목을 입력해 주세요. |
  | 보기1~보기N | 텍스트 N개 | 예 | 처음 3칸 제공, 최대 6칸. 모든 보기가 공백이 아니어야 함. 추가된 마지막 보기가 비어 있으면 새 보기를 더 추가할 수 없음 | 보기는 3개에서 6개까지 입력해 주세요. / 모든 보기를 입력해 주세요. |
  | 정답 선택 | 단일 선택 "1번"~"N번"(보기 수만큼) | 예 | 선택된 번호가 현재 보기 수 이내여야 함 | 정답 번호를 선택해 주세요. / 정답 번호가 입력한 보기 수를 초과했습니다. |
  | 정답 제목 | 텍스트 | 예 | 공백만 불가 | 정답 제목을 입력해 주세요. |
  | 정답 텍스트 | 텍스트 | 예 | 공백만 불가 | 정답 텍스트를 입력해 주세요. |
  | 오답 제목 | 텍스트 | 예 | 공백만 불가 | 오답 제목을 입력해 주세요. |
  | 오답 텍스트 | 텍스트 | 예 | 공백만 불가 | 오답 텍스트를 입력해 주세요. |
- **표시 데이터**: 보기 개수 안내 "({현재}/6)"와 상황별 안내 문구 — 기본: "보기는 3개에서 6개까지 입력할 수 있어요. 저장하려면 모든 보기를 입력해 주세요." / 마지막 보기 비어 있음: "마지막 보기를 입력하면 다음 보기를 추가할 수 있어요." / 6개 도달: "보기는 최대 6개까지 입력할 수 있어요." 동작 라벨 "보기 추가", 보기별 "삭제"
- **상태**:
  - "보기 추가"는 6개에 도달했거나 추가된 마지막 보기가 비어 있으면 비활성.
  - 보기를 삭제할 때 정답 번호 보정: 삭제한 보기가 정답이었으면 정답 선택이 초기화, 삭제한 보기보다 뒤 번호가 정답이었으면 번호가 하나 당겨짐.
  - 검증 실패 포커스: 비어 있는 첫 보기 → 정답 선택.
  - 보기 오류·정답 오류는 해당 위치에 즉시 낭독되는 오류 문구로 표시.
- **결과**: "저장" 성공 시 TRP-14
- **정책·예외 규칙**: 보기 개수 범위 3~6은 화면과 전송 직전 모두에서 재검사. 사용자에게 보이는 퀴즈 풀이 화면(TRP-03)은 보기를 무작위로 섞으므로 정답 위치가 등록 순서와 무관하게 섞여 보인다.
- **데스크톱/모바일 차이**: 없음

### TRP-14 나들이 저장(업로드 포함)
- **대상 사용자**: 관리자만
- **진입 경로**: 3단계 "저장"
- **흐름**: 1. 3단계 검증 통과 확인(1·2단계는 "다음" 시점에 이미 통과한 것으로 간주). 2. 이미지 순차 업로드: 로고 → 지도 1 → (있으면) 지도 2. 3. 업로드된 파일 정보와 입력값으로 나들이 생성 요청(날짜는 YYYY-MM-DD, 이름·텍스트는 앞뒤 공백 제거, 선택된 정답 번호에 해당하는 보기만 정답으로 표시). 4. 성공하면 목록 데이터 갱신.
- **상태**:
  - 처리 중: "저장" 처리 중 표시, 중복 클릭 무시
  - 성공: 임시저장 삭제 후 나들이 목록으로 이동(별도 성공 알림 없음. 목록에서 확인)
  - 실패(저장 버튼 위 오류 문구, 입력 내용은 유지, 다시 "저장" 가능). 현재 문구:
    - 네트워크 끊김: 네트워크에 연결할 수 없어요. 연결을 확인하고 다시 저장해 주세요.
    - 401: 로그인이 풀렸어요. 다시 로그인한 뒤 저장해 주세요.
    - 403: 이 기록을 저장할 권한이 없어요.
    - 413: 파일이 너무 커서 업로드하지 못했어요. 10MB 이하 이미지로 다시 시도해 주세요.
    - 429: 요청이 너무 많아요. 잠시 뒤 다시 저장해 주세요.
    - 5xx: 서버에 문제가 생겨 저장하지 못했어요. 잠시 뒤 다시 시도해 주세요.
    - 그 밖의 서버 오류: 저장하지 못했어요. 입력을 확인하고 다시 시도해 주세요.
    - 응답 형식 오류: 저장은 됐지만 응답을 읽지 못했어요. 목록에서 확인해 주세요.
    - 기타: 저장하지 못했어요. 잠시 뒤 다시 시도해 주세요.
- **결과**: 목록 화면으로 이동, 새 기록이 목록에 나타남
- **정책·예외 규칙**: 업로드가 일부 성공한 뒤 실패하면 이미 올라간 파일은 서버에 남는다(정리 동작 없음). 이 경우 재시도하면 파일이 다시 올라간다. 수정·삭제 기능은 나들이 영역에 존재하지 않는다.
- **데스크톱/모바일 차이**: 없음

## 기술 제약
- 이미지 파일 업로드: 로고·지도 모두 jpg/jpeg/png/gif/svg 만 허용, 파일당 10MB 이하(화면 검증 및 서버 413 응답 안내).
- 업로드는 파일마다 별도 요청으로 순차 진행(로고 → 지도 1 → 지도 2). 완료 시점에 나들이 생성 요청이 한 번 더 나간다.
- 이미지 표시는 인증 쿠키가 브라우저 요청에 자동 첨부되는 방식에 의존한다. 목록 썸네일은 축소 변형을 요청하고 지도는 원본을 요청한다. 로드 실패는 이미지 오류 이벤트로만 감지한다.
- 퀴즈 정답 판정과 정답 안내문은 서버에서만 확인할 수 있다(보기 선택 시마다 서버 호출).
- 임시저장은 브라우저 탭 세션 저장소를 사용하며, 저장소를 못 쓰는 환경(사생활 보호 모드 등)에서는 조용히 임시저장이 생략된다. 파일은 임시저장 불가.
- 드라이브 링크는 새 탭 열기(팝업 차단 설정의 영향을 받을 수 있음).
- 나들이 유형 값은 AYO / RYU 두 가지로 고정(서버 계약). 추가하려면 서버 변경 필요.
- 지도 SDK(카카오 지도), 도보 경로 계산, 주소 검색 등 위치 관련 기능은 나들이 영역이 사용하지 않는다(임장 영역 전용). 브라우저 위치 권한도 요구하지 않는다.
- 날짜·목록은 서버가 준 순서 그대로이며 페이지네이션이 없다(전체 목록 일괄 조회).

## 확인 필요
- 등록 경로(map/register)에는 관리자 제한이 걸려 있지 않다. 일반 사용자가 주소로 직접 들어가 작성까지 할 수 있고, 최종 거부는 서버 응답(403 문구)에 의존한다. 의도된 설계인지, 경로 단계 관리자 제한을 둘 것인지 기획 확인 필요.
- 상세 화면이 퀴즈 통과를 검사하지 않아 주소 직접 입력으로 퀴즈 없이 열린다. 서버 측에서 막는지는 코드로 확인 불가.
- 상세 응답의 나들이 이름·날짜·유형·로고는 화면에 쓰이지 않는다. 리디자인에서 상세 헤더에 보여 줄지 여부는 기획 결정 사항(데이터는 이미 제공됨).
- 목록 항목의 description(설명)은 표시만 하고 등록 화면에서 입력받지 않는다. 데이터 출처 불명.
- nextButtonText/previousButtonText 필드명이 "다음/이전"을 시사하나 실제로는 지도 1/지도 2 전환 라벨로 쓰인다.
- 목록과 상세 화면 제목, 상세의 안내 "암호 🔒 : 입사일"에 서비스명 등 브랜드성 문구가 현재 포함되어 있다.
- 모바일에서 등록·상세는 하위 화면 틀(뒤로가기 구조)로 열리는 설정이 있으나, 그 틀의 상세 기능(뒤로가기 동작 등)은 공통 레이아웃 소관이라 이 문서에서 확정하지 않았다.
- 목록 정렬 기준(최신순 여부)은 서버 응답 순서에 의존하며 코드로는 확정 불가.
- 등록 시 지도 1 선택 후 단계 이동 때 선택한 파일이 유지되는지(단계 간 메모리 유지)는 코드상 유지되나, 새로고침 시 파일 소실은 위 안내로만 알려 준다.
