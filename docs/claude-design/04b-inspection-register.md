# 임장 — 계획 등록 마법사, 회차·매물 수정

> 상위 문서: [04-inspection.md](./04-inspection.md) (개요·URL·데이터 필드 사전·기술 제약·확인 필요). 이 파일의 기능 ID는 전체 임장 영역에서 유일하다.

## 기능 목록
### INS-30 임장 계획 1단계: 지역 고르기
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 임장 계획하기(INS-06)
- **흐름**:
  1. 제목 "임장 계획하기"(데스크톱은 화면 제목으로 보임, 모바일은 보조 기술용으로만 존재). 상단 단계 표시 "1 지역 / 2 기본 정보 / 3 확인 매물"(접근성 이름 "임장 계획 단계").
  2. 단계 안내: "어느 지역을 임장할까요?" / "먼저 임장할 지역을 고르거나 새로 만들어 주세요."
  3. "지역 검색"(안내 "동네 이름으로 검색")에 입력하면 기존 지역을 최대 10건 조회해 보인다. 각 결과: 지역명, 설명, "임장 N회 · 최근 yyyy.mm.dd", "이 지역에 임장 계획 추가".
  4. 지역을 누르면 선택된다(선택 상태 표시). 선택 요약: "선택한 지역 {이름}" (새 지역이면 " (새 지역)" 추가).
  5. "다음"으로 2단계 이동(INS-35).
- **상태**:
  - 검색 중: "찾는 중..."
  - 검색 결과 없음(검색어 있을 때): 현재 문구: "\"{검색어}\"와 일치하는 지역이 없어요. 아래에서 새로 만들어 주세요."
  - 선택 없이 다음: 다음 버튼 비활성 + 이유 현재 문구: "먼저 지역을 고르거나 새로 만들어 주세요." (이동 시도 시 같은 문구가 오류로 표시)
- **결과**: 지역 선택이 마법사 상태에 보관됨. 이 시점에는 서버에 아무것도 저장하지 않는다.
- **정책·예외 규칙**: 선택은 하나만 가능(기존 지역 또는 새 지역).
- **데스크톱/모바일 차이**: 제목 표시만 다름
### INS-31 새 지역 만들어 선택
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 1단계의 "+ 새 지역 만들기"
- **흐름**: 입력이 열리면 지역명(필수)과 지역 설명("선택 입력")을 쓰고 "이 지역으로 선택"을 누른다. 선택되면 요약에 "(새 지역)"으로 표시. 실제 지역 생성은 2단계에서 예정일이 채워져 첫 저장이 일어날 때 회차와 함께 만들어진다.
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 지역명 | 텍스트 | 예 | 공백 제거 후 비어 있으면 "이 지역으로 선택" 비활성 | 다음 이동 시 비어 있으면 현재 문구: "지역명을 입력해 주세요." |
  | 지역 설명 | 텍스트 | 아니오 | | 없음 |
- **결과**: 새 지역이 선택 상태가 됨. 다시 기존 지역을 누르면 그쪽으로 바뀐다.
- **데스크톱/모바일 차이**: 없음
### INS-32 임장 계획 2단계: 예정일 입력과 자동 저장
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 1단계에서 "다음"
- **흐름**:
  1. 제목 "임장 계획" / 안내 "예정일만 있으면 됩니다. 메모와 태그는 나중에 채워도 돼요." / "다녀온 뒤 임장 수정 화면에서 결과를 쓰고 완료해요"
  2. 예정일(날짜)과 예정 시각(시간)을 모두 입력해야 다음으로 갈 수 있다.
  3. 전체 메모와 태그(INS-33)는 선택.
  4. 예정일과 시각이 채워진 뒤에는 입력이 멈추고 약 2초 뒤 자동 저장한다. 처음 저장은 회차(필요하면 새 지역 포함)를 생성하고, 이후는 같은 회차를 갱신한다. 저장 상태 줄: 저장 전 현재 문구: "아직 저장되지 않았습니다", 저장 후 "{hh}:{mm}에 임시 저장됨".
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 예정일 | 날짜 | 예 | 날짜와 시각이 모두 있어야 저장·진행 | 현재 문구: "예정일과 시각을 입력해 주세요." |
  | 예정 시각 | 시간 | 예 | 위와 같음 | (예정일 오류와 동일) |
  | 전체 메모 | 여러 줄(최대 5,000자) | 아니오 | | 없음 |
  | 태그 | INS-33 | 아니오 | | 없음 |
  - 진행 불가 이유 줄 현재 문구: "예정일과 시각을 입력해야 다음으로 갈 수 있어요."
- **상태**: 자동 저장 실패 시 서버 메시지 또는 현재 문구: "자동 저장에 실패했어요. 잠시 뒤 다시 시도해 주세요." (다음 변경·이동·이탈 시 같은 내용을 다시 저장 시도)
- **결과**: 회차가 계획 상태(작성 중, 최초 완료 없음)로 서버에 존재하게 된다.
- **정책·예외 규칙**: 예정일·시각이 채워지기 전에는 서버에 아무것도 보내지 않는다. 저장이 진행 중이면 겹쳐 보내지 않고 다음 변경 때 다시 저장한다. 과거 날짜도 입력 가능(제한 없음). 마법사에는 재방문 의사·한줄평·장점/단점·사진 입력이 없다(계획 전용, 결과는 회차 수정에서 입력).
- **데스크톱/모바일 차이**: 없음
### INS-33 태그 입력 (회차)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 계획 2단계 및 회차 수정의 "태그"
- **흐름**: 입력창에 태그를 쓰고 Enter(안내 "태그를 입력하고 Enter")로 추가한다. 추가된 태그는 "{태그} ×" 형태로 보이며 누르면 지워진다(접근성 이름 "태그 {태그} 지우기"). 자주 쓴 태그(최대 8개, 이미 선택한 것 제외)가 "자주 쓴 태그" 아래 "+ {태그}"로 제안되며 누르면 추가된다.
- **입력 항목**: 태그 — 텍스트, 필수 아님, 앞뒤 공백 제거, 빈 값·중복 무시, 화면상 길이/개수 제한 없음(서버 제약은 확인 필요)
- **상태**: AI 초안 작성 중에는 입력·삭제 잠금(INS-52)
- **데스크톱/모바일 차이**: 없음
### INS-34 임장 계획 3단계: 확인 매물 정리
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 2단계에서 "다음"(회차가 저장된 뒤에만 내용이 보임), 단계 표시에서 3 선택, 또는 `register?draft={회차ID}`로 진입
- **흐름**:
  1. 제목 "확인 매물" / "매물 없이도 계획을 저장할 수 있어요. 나중에 다시 들어와 이어서 쓸 수 있어요." / 보조: "매물마다 그 매물을 만든 시점에 활성화된 질문 구성으로 문답이 고정됩니다. 나중에 질문이 바뀌어도 이미 만든 매물에는 반영되지 않아요."
  2. 매물이 있으면 방문 순서(INS-18)와 추천 순서 정렬(INS-20)이 보이고, 매물 목록이 방문 순서대로 나열된다.
  3. 매물 한 줄: 순서 이동 조작, "단지명 · 동·호수", 작성 중 배지+이유(회차가 "수정 중"일 때만), 관심도, 편집 진입 동작("이어서 쓰기" — 작성 중인 매물 / "수정" — 완료된 매물). 편집 진입은 매물 편집(INS-64)으로 이동하며 끝나면 이 마법사로 돌아온다.
  4. **순서 변경**: 각 줄을 끌어 놓아 위치를 바꾸거나, 줄마다 "{단지명 · 동·호수} 위로 이동"/"… 아래로 이동" 버튼(첫 줄은 위로, 마지막 줄은 아래로 비활성)으로 한 칸씩 옮긴다. 변경 즉시 서버에 저장하고 화면에도 바로 반영. 실패하면 원래 순서로 복구하고 현재 문구: "순서를 바꾸지 못했어요. 원래 순서로 되돌렸어요. 잠시 뒤 다시 시도해 주세요."
  5. 아래에 "+ 매물 추가"(INS-40).
  6. "계획 저장"(INS-37)으로 마무리.
- **상태**:
  - 로딩: 자리표시.
  - 매물 없음: 현재 문구: "아직 추가한 매물이 없어요."
  - 회차가 아직 저장되지 않았으면(2단계 자동 저장 전) 3단계에는 내용이 표시되지 않는다(확인 필요).
- **결과**: 매물 추가·순서·편집 결과가 즉시 서버 반영
- **정책·예외 규칙**: 이 목록의 배열 순서가 곧 방문 순서이며 이름순 등으로 다시 정렬하지 않는다. 인접 두 줄을 바꿀 때는 두 줄의 순서값만 맞바꿔 보내고, 순서값이 같아 구분이 안 되면 전체를 0부터 다시 매겨 보낸다.
- **데스크톱/모바일 차이**: 순서 이동 버튼은 가로 아이콘 버튼. 끌어 놓기는 터치 환경에서 동작하지 않을 수 있어 버튼이 기본 경로.
### INS-35 마법사 단계 이동 규칙
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 마법사 하단 "이전"/"다음"/"나가기", 상단 단계 표시
- **규칙**:
  1. "다음": 1단계는 지역 선택, 2단계는 예정일·시각이 있어야 활성. 비활성일 때 이유 줄을 함께 보인다(INS-30, INS-32 문구). 눌렀을 때 검증 실패 시 해당 항목 오류 표시.
  2. "이전": 2·3단계에서만 보이며 입력값을 유지한 채 앞 단계로.
  3. 단계 표시(1·2·3): 지난 단계/현재/앞 단계로 구분(현재 단계에 현재 위치 표시). **앞 단계로는 언제나 이동 가능**. 앞으로 건너뛰기는 검증을 통과해야 하고(1→2는 지역 선택, 2→3은 지역+예정일), 아직 회차가 저장되기 전에는 앞 단계 항목이 비활성이다. 3단계에서는 "다음" 대신 "계획 저장"이 나온다.
  4. "나가기": 저장 확인 없이 지역 목록으로 이동. 이미 자동 저장된 계획은 남는다. 대기 중이던 저장은 이탈 시 바로 전송.
- **상태**: 자동 저장 오류 문구는 하단에 오류로 표시(INS-32)
- **데스크톱/모바일 차이**: 없음
### INS-36 저장된 계획 이어서 하기
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: `register?draft={회차ID}` — 마법사에서 시작한 매물 편집이 끝나면 이 주소로 돌아옴
- **흐름**: 해당 회차를 불러와 지역·예정일·메모·태그를 채우고 3단계에서 시작한다. 불러온 값은 이미 저장된 상태이므로 열기만 해서는 다시 저장하지 않는다.
- **상태**: 로딩 자리표시. 실패 현재 문구: "이어서 쓸 기록을 불러오지 못했어요" / "링크가 잘못됐거나 삭제된 기록일 수 있어요." — 재시도 동작은 지역 목록으로 이동.
- **데스크톱/모바일 차이**: 없음
### INS-37 계획 저장
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 3단계의 "계획 저장"
- **흐름**: 대기 중인 자동 저장이 있으면 끝날 때까지 기다린 뒤 마지막으로 한 번 더 저장하고, 지역 상세의 해당 회차(`visit` 지정)로 이동한다. 상태를 바꾸지 않는다(계획은 계획 상태 그대로).
- **상태**: 처리 중 버튼 로딩. 저장할 회차가 없으면(예정일 미입력 등) 이동하지 않는다. 저장 실패 시 하단 오류 문구 표시, 이동 없음.
- **결과**: 지역 상세에서 새 계획 회차(배지 "계획")를 본다. 지역 정보가 없으면 지역 목록으로.
- **정책·예외 규칙**: 다녀온 뒤 결과 작성과 완료는 회차 수정(INS-50~54)에서 한다.
- **데스크톱/모바일 차이**: 없음
### INS-40 매물 추가 (회차 안)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 등록 3단계 또는 지역 상세 확인 매물 영역의 "+ 매물 추가"
- **흐름**:
  1. 누르면 같은 자리에 입력이 펼쳐진다(이때 단지명 제안 목록을 불러옴).
  2. 단지/건물명(필수), 동·호수(선택), 주소(선택, INS-41)를 입력한다.
  3. "추가하고 계속 쓰기"를 누르면 매물을 만들고 곧바로 매물 편집(INS-64)으로 이동한다. 지역 상세에서 시작한 경우 편집이 끝나면 지역 상세로, 마법사에서 시작했으면 마법사로 돌아온다.
  4. "취소"는 입력을 닫고 값을 비운다.
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 단지/건물명 | 텍스트(같은 지역의 기존 단지명 제안) | 예 | 공백 제거 후 비어 있으면 추가 불가. 안내: "같은 이름이어야 회차 간 매물이 연결됩니다." | 현재 문구: "단지명을 입력해 주세요." |
  | 동·호수 | 텍스트 | 아니오 | 안내: "임장 전이라면 비워 둘 수 있어요." 비우면 저장되지 않음(미정) | 없음 |
  | 주소 (선택) | 주소 검색 선택 | 아니오 | INS-41 | INS-41 |
- **상태**:
  - 처리 중 버튼 로딩.
  - 일반 실패: 현재 문구: "매물을 추가하지 못했어요. 잠시 뒤 다시 시도해 주세요."
  - **주소 때문에 실패**(좌표 확인 실패 등): 매물은 만들어지지 않고 입력은 그대로 유지된 채 안내가 나온다. 현재 문구: "주소를 저장하지 못했습니다. 위치 없이 등록할까요?" + 사유 한 줄 + "위치는 나중에 매물 수정 화면에서 다시 넣을 수 있어요." 동작: "위치 없이 등록"(주소 없이 다시 추가) / "다른 주소 고르기"(주소를 비우고 주소 입력에 초점). 자동 재시도 없음.
  - 서비스가 주소 기능이 꺼져 있다고 응답하면 이 입력의 주소 필드가 비활성(사유 "지금은 주소를 쓸 수 없어요").
- **결과**: 새 매물이 방문 순서의 맨 뒤에 추가되고 편집 화면으로 이동.
- **정책·예외 규칙**: 주소를 고르면 단지/건물명이 비어 있을 때 건물명(있으면)으로 자동 채운다. 동·호수 없이도 매물을 만들 수 있다(계획 단계).
- **데스크톱/모바일 차이**: 없음
### INS-50 회차 수정 (기본 정보 편집과 자동 저장)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 지역 상세 회차 헤더의 "이 임장 수정"
- **흐름**:
  1. 진입 시 항상 서버에서 최신 값을 새로 불러온다. 상위 경로 "{지역명}"(지역 상세로 이동), 제목 "임장 기록 수정".
  2. 항목을 편집하면 입력이 멈춘 약 2초 뒤 자동 저장한다(열기만 해서는 저장하지 않음). 저장 상태 줄: "{hh}:{mm}에 저장됨". 화면을 떠날 때 대기 중인 저장은 즉시 전송.
  3. 하단에 "임장 기록 삭제"(INS-55), "지금 상태로 완료 시도"/"완료 해제하고 수정"(INS-54).
- **입력 항목**:
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 임장 일시(날짜) | 날짜 | 예(표시) | 날짜·시각 중 하나라도 비면 저장하지 않음(오류 안내 없음) | 없음 |
  | 시각 | 시간 | 예(표시) | 위와 같음 | 없음 |
  | 재방문 의사 | 3택1 "살고싶어/고민/안살아" | 예(표시) | 저장 시 강제하지 않음. 완료 시 서버가 검사 | 완료 시 서버 메시지 |
  | 전체 메모 | 여러 줄(최대 5,000자) | 아니오 | | 없음 |
  | 한줄평 | 텍스트(최대 300자) | 아니오 | 안내 "선택 입력" | 없음 |
  | 장점 / 단점 | 여러 줄 | 아니오 | 줄 단위로 목록 표시됨 | 없음 |
  | 태그 | INS-33 | 아니오 | | 없음 |
  | 임장 사진 | INS-51 | 아니오 | | |
- **상태**:
  - 로딩 자리표시. 에러 현재 문구: "임장 기록을 불러오지 못했어요" + 다시 시도.
  - 저장 실패: 서버 메시지 또는 현재 문구: "저장하지 못했어요. 잠시 뒤 다시 시도해 주세요."
- **결과**: 회차 데이터 갱신(지역 상세·목록에 반영)
- **정책·예외 규칙**: 동시 수정에 대한 충돌 감지가 없어 마지막 저장이 이긴다. 비어 있는 텍스트는 "값 없음"으로 보낸다.
- **데스크톱/모바일 차이**: 없음
### INS-51 사진 관리 (회차·매물 공통)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 회차 수정의 "임장 사진", 매물 편집의 "매물 사진"
- **흐름**:
  1. 사진을 끌어다 놓거나 선택해서 추가한다(안내 "사진을 끌어다 놓거나 선택하세요", "JPG · PNG · 최대 50MB, 여러 장 선택 가능"). 추가 즉시 미리보기가 보이고 업로드는 바로 시작한다.
  2. 진행 현재 문구: "사진 업로드 중 {완료}/{전체}" — 한 번에 최대 6장·약 100MB씩 나눠 순차 업로드.
  3. 각 사진 한 줄: 끌기 손잡이("끌어서 순서 바꾸기"), 썸네일(맨 앞 사진에 "대표"), 캡션 입력(안내 "캡션 (선택) — 비우면 대체 텍스트 없음", 접근성 이름 "{n}번째 사진 캡션"), "삭제"(접근성 이름 "{n}번째 사진 삭제").
  4. 순서는 끌어 놓아 바꾸며 **맨 앞이 대표 사진**이 된다. 회차 수정에서는 순서 변경이 서버에 즉시 반영되고(저장된 사진일 때), 추가·삭제·캡션은 자동 저장에 실린다.
- **상태**:
  - 50MB 초과 파일: 현재 문구: "50MB를 넘는 사진 {n}장은 올리지 않았어요." (나머지는 업로드)
  - 용량 초과(413): "사진 용량이 너무 커서 올리지 못했어요. 50MB 이하 사진으로 다시 시도해 주세요."
  - 네트워크 오류: "사진을 올리지 못했어요. 네트워크 연결을 확인해 주세요."
  - 기타: "사진을 올리지 못했어요. {사유}" 또는 "사진을 올리지 못했어요. 잠시 뒤 다시 시도해 주세요."
  - 업로드 실패 시 해당 임시 항목은 목록에서 제거된다.
- **결과**: 저장 시 사진 묶음 전체를 현재 화면 순서로 교체 저장한다.
- **정책·예외 규칙**: 안내 형식은 JPG/PNG. 사진 개수 제한은 화면에 없음. 별도 대표 지정 동작은 없고 순서 맨 앞이 대표.
- **데스크톱/모바일 차이**: 끌어 놓기 중심이며 터치 환경에서의 순서 변경 대체 수단은 없다(확인 필요).
### INS-52 메모로 초안 쓰기 (AI 후기 초안; 회차·매물 공통)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 회차 수정의 전체 메모 아래, 매물 편집의 메모 아래 (등록 마법사 계획 단계에서는 제공하지 않음)
- **흐름**:
  1. 안내 문구(대기): "한줄평·장점·단점·태그를 채워 드려요". 버튼 "메모로 초안 쓰기".
  2. 메모가 비어 있으면 현재 문구: "메모를 먼저 적어 주세요. 메모를 바탕으로 초안을 써 드려요."
  3. 이미 한줄평·장점·단점·태그 중 하나라도 적혀 있으면 먼저 확인 절차: 제목 "적어 둔 후기를 초안으로 바꿀까요?" / "한줄평·장점·단점·태그에 적어 둔 내용이 AI 초안으로 바뀌어요. 메모는 그대로 남아요." / 버튼 "초안으로 바꾸기" / 취소 "그대로 둘게요".
  4. 진행 중: 버튼 "초안 쓰는 중"(로딩), 안내 "메모를 읽고 있어요. 길면 30초쯤 걸려요". 이 동안 채워질 입력(메모·한줄평·장점·단점·태그)은 읽기 전용.
  5. 성공: 초안 중 **내용이 있는 항목만** 해당 입력에 채우고(빈 항목은 건드리지 않음) 채워진 항목이 초안임이 보이도록 표시. 안내 "초안을 채웠어요. 다듬어서 저장해 주세요". 버튼은 "초안 다시 쓰기"로 바뀐다. 채운 값은 자동 저장 대상이 된다.
- **상태**: 실패 현재 문구(서버가 사용자용 사유를 주면 그대로, 아니면): "초안을 만들지 못했어요. 잠시 뒤 다시 시도해 주세요." 매물 편집에서 문답 저장이 실패하면: "문답을 저장하지 못해 초안을 만들 수 없어요. 잠시 뒤 다시 시도해 주세요."
- **결과**: 입력 채움(서버에는 초안을 별도 저장하지 않음)
- **정책·예외 규칙**: 메모 길이 최대 5,000자. 매물 초안은 저장된 문답도 근거로 쓰므로 대기 중인 문답을 먼저 저장한 뒤 요청한다. 화면을 떠나면 진행 결과를 반영하지 않는다.
- **데스크톱/모바일 차이**: 없음
### INS-54 임장 완료 시도 / 완료 해제
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 회차 수정 하단 버튼
- **흐름**:
  1. 작성 중이면 "지금 상태로 완료 시도", 완료 상태이면 "완료 해제하고 수정" 버튼이 나온다.
  2. 누르면 먼저 대기 중인 자동 저장을 보내고 나서 상태 변경을 요청한다. 완료 가능 여부는 서버가 판단한다(임장 일시·재방문 의사, 매물 완료 여부 등).
  3. 성공하면 화면의 상태 안내가 바뀐다(이동 없음).
- **상태**: 처리 중 버튼 로딩. 실패 시 서버 메시지 또는 현재 문구: "상태를 바꾸지 못했어요." (하단 오류)
- **결과**: 회차가 완료로 바뀌면 최초 완료 시각이 기록되어 이후 "계획"으로 돌아가지 않는다. 완료 해제는 "수정 중"이 된다.
- **정책·예외 규칙**: 완료 조건 안내 문구는 INS-07 참고.
- **데스크톱/모바일 차이**: 없음
### INS-55 회차 삭제 (수정 화면)

- **흐름**: 확인 절차 제목 "이 임장 기록을 삭제할까요?" / 현재 문구: "매물 {n}건과 사진 {m}장이 함께 삭제돼요." / 버튼 "삭제", 취소 "계속 둘게요". 성공하면 해당 지역 상세로 이동한다.

- **정책·예외 규칙**: 복구 불가. (지역 상세의 삭제(INS-16)와 문구가 다름)
- **데스크톱/모바일 차이**: 없음
### INS-67 매물 문답 작성
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 매물 편집의 문답 영역
- **흐름**:
  1. 문답은 매물을 만든 시점의 질문 구성이 분류별로 묶여 나온다(분류 순서 → 질문 순서). 분류 머리에 필수 현황: 남은 게 있으면 "필수 {n}개 남음", 모두 답했으면 "필수 모두 답함"(필수 질문이 없으면 표시 없음).
  2. 질문마다: 질문 문구(필수는 *), 설명(있으면), 입력, 필수인데 미답변이면 현재 문구: "이 질문은 꼭 답해야 매물을 완료할 수 있어요." 질문이 개정/비활성된 경우 배지 "이전 버전 문항", "비활성 질문"(입력은 그대로 가능).
  3. 입력 유형: 한 줄 글/긴 글(비우면 미답변), 숫자(뒤에 단위 표시, 비우면 미답변), 예 / 아니오(둘 중 선택), 별점(1~5), 단일 선택(보기 중 하나), 다중 선택(여러 개, 모두 해제하면 미답변).
  4. 어떤 입력이든 마지막 입력 뒤 약 2초 뒤에 질문별 최신 값만 모아 한 번에 저장한다. 화면을 떠날 때 대기분은 바로 전송.
- **상태**: 저장 실패 시 별도 문구가 없다(확인 필요).
- **결과**: 답변 즉시 "미답변" 경고가 사라지고 완료 조건에 반영
- **정책·예외 규칙**: 답변은 한 유형의 값만 보낼 수 있다. 질문 구성이 나중에 바뀌어도 기존 매물에는 영향 없음.
- **데스크톱/모바일 차이**: 없음
### INS-69 매물 완료 / 작성 중으로 저장
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 매물 편집 하단 "매물 완료", "작성 중으로 저장"
- **흐름**:
  1. "매물 완료": 완료 조건(단지명·동·호수 입력, 관심도 입력, 필수 문답 모두 답함)을 채우기 전에는 비활성. 누르면 대기 중인 저장(기본 정보, 문답)을 먼저 보내고 완료로 바꾼 뒤 돌아가기 규칙(INS-71)대로 이동한다.
  2. "작성 중으로 저장": 이동하지 않고 현재 내용을 저장한다. 이미 완료된 매물이면 작성 중 상태로 되돌린다.
- **상태**: 완료 요청이 거부되면 서버 메시지 또는 현재 문구: "완료할 수 없어요. 잠시 뒤 다시 시도해 주세요." (하단 오류). 처리 중 완료 버튼 로딩. "작성 중으로 저장"은 성공 확인 안내가 따로 없다.
- **정책·예외 규칙**: 완료 조건은 INS-64의 안내 문구와 같다.
- **데스크톱/모바일 차이**: 없음

### INS-71 매물 편집 후 돌아가기 규칙
- **대상 사용자**: 로그인 사용자 전체
- **규칙**: 완료·삭제 후 이동 위치는 진입 경로에 따라 다르다. 지역 상세에서 시작한 편집(`from=area`)은 해당 회차가 선택된 지역 상세로, 그렇지 않으면 등록 마법사(`register?draft={회차ID}`)로 돌아간다. 매물 상세에서 시작한 편집도 `from=area`가 없으므로 마법사로 돌아간다(확인 필요). 편집 화면 상단의 상위 경로 링크는 항상 지역 상세로 간다.
- **데스크톱/모바일 차이**: 없음
