# 프로필

## 개요
사용자는 자기 계정 정보(표시 이름, 비밀번호, 프로필 이미지)를 확인·수정하고 화면 밝기와 로그아웃을 할 수 있다. 정보 수정은 보안을 위해 먼저 현재 비밀번호로 본인 확인을 해야 한다. **데스크톱과 모바일의 구조가 다르다**: 데스크톱은 별도 화면 없이 헤더의 프로필 메뉴에서 열리는 단계형 창으로, 모바일은 전용 화면 3개(마이페이지 → 본인 확인 → 정보 수정)로 제공된다.

## URL
| 경로 (/main, /mobile 공통 뒤쪽) | 화면 의미 | 접근 권한 | 비고 |
|---|---|---|---|
| `/profile` | 데스크톱: 화면 없음 → `/main`(홈)으로 즉시 이동. 모바일: 마이페이지 | 로그인 | 모바일 전용 화면. 상세형 틀, 제목 "마이페이지", 뒤로가기 → 홈 |
| `/profile/verify` | 데스크톱: 화면 없음 → `/main`(홈)으로 이동. 모바일: 본인 확인 | 로그인 | **모바일 전용 화면**. 제목 "본인 확인", 뒤로가기 → 마이페이지 |
| `/profile/edit` | 데스크톱: 화면 없음 → `/main`(홈)으로 이동. 모바일: 사용자 정보 수정 | 로그인 (+ 직전 본인 확인 통과 필요) | **모바일 전용 화면**. 제목 "사용자 정보 수정", 뒤로가기 → 마이페이지 |

## 기능 목록

### PRF-01 프로필 진입 (아바타/메뉴)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 데스크톱 — 헤더 우측 프로필 버튼(접근성 이름 "내 프로필") → 프로필 메뉴. 모바일 — 상단바 우측 프로필 버튼(접근성 이름 "내 프로필", 아바타) → `/mobile/profile`
- **흐름**: 데스크톱은 메뉴가 열려 "사용자 정보 수정 / 화면 밝기 / 로그아웃"을 제공(COM-09). 모바일은 마이페이지 화면으로 이동.
- **표시 데이터**: 프로필 이미지(작은 크기), 이름, "로그인 계정" 표기
- **상태**: 프로필 로딩 중 — 아바타 로딩 표시, 이름은 로그인 시점 이름으로 대체 표시. 프로필 이미지 없음 — 기본 아바타.
- **정책·예외 규칙**: 프로필 조회는 로그인 토큰이 확보된 뒤에만 수행.
- **데스크톱/모바일 차이**: 데스크톱은 메뉴(화면 이동 없음), 모바일은 전용 마이페이지 화면.

### PRF-02 마이페이지 보기 (모바일 전용 화면)
- **대상 사용자**: 로그인 사용자 전체 (모바일)
- **진입 경로**: 모바일 상단바 프로필 버튼
- **표시 데이터**: 프로필 이미지(큰 크기, 이미지 있을 때 접근성 이름 "{이름} 프로필"), 이름, "로그인 계정"; 구역 "계정" — "사용자 정보 수정"; 구역 "화면" — 화면 밝기 선택(COM-13); "로그아웃" 버튼
- **흐름/동작**: "사용자 정보 수정" → 본인 확인 허용 기록을 먼저 폐기한 뒤 `/mobile/profile/verify` 로 이동. 로그아웃은 COM-06.
- **상태**: 로딩/실패 시 이름은 로그인 시점 이름으로 대체. 로그아웃 처리 중 "로그아웃 중…".
- **데스크톱/모바일 차이**: 모바일 전용(데스크톱은 메뉴로 대체)

### PRF-03 본인 확인 (현재 비밀번호 확인)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 데스크톱 — 프로필 메뉴의 "사용자 정보 수정"(메뉴가 닫히고 창이 열림, 창 제목 "본인 확인", 닫기 버튼 접근성 이름 "닫기"). 모바일 — 마이페이지의 "사용자 정보 수정" → `/mobile/profile/verify`
- **흐름**: 1. 열기 전에 기존 본인 확인 허용 기록을 폐기 2. 현재 비밀번호 입력 3. "확인" 제출 4. 서버가 일치를 확인하면 이 사용자에 대한 5분짜리 수정 허용을 기록하고 수정 단계로 이동 — 데스크톱은 같은 창이 "사용자 정보 수정" 창으로 전환, 모바일은 `/mobile/profile/edit` 로 이동(히스토리 대체: 뒤로가기로 본인 확인 화면에 돌아오지 않음) 5. 불일치/오류면 같은 화면에 오류 표시
- **입력 항목**:

| 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
|---|---|---|---|---|
| 현재 비밀번호 | 비밀번호(표시/숨기기 토글, 접근성 이름 "비밀번호 표시" / "비밀번호 숨기기"). 자리표시: 데스크톱 "현재 비밀번호를 입력해 주세요", 모바일 "현재 비밀번호" | 예 | 비어 있으면 제출 불가("확인" 비활성). 입력을 바꾸면 이전 오류는 사라짐 | 서버가 400 또는 401 로 거절: "현재 비밀번호가 일치하지 않습니다. 다시 입력해 주세요." / 그 외(네트워크·서버 오류): "일시적인 오류로 확인하지 못했어요. 잠시 후 다시 시도해 주세요." |

- **표시 데이터**: 제목 "본인 확인", 안내 현재 문구: "사용자 정보를 수정하려면 현재 비밀번호로 본인 확인이 필요해요."
- **상태**: 처리 중 — 버튼 문구 "확인 중…" + 스피너, 비활성, 중복 제출 방지. 오류 — 알림 역할 문구 + 입력 오류 표시. 데스크톱은 열리면 비밀번호 입력에 자동 포커스.
- **결과**: 수정 단계로 이동
- **정책·예외 규칙**: 수정 허용은 **5분 유효**, 같은 사용자 한정, 세션 저장소(탭 단위)에 기록. 로그인·로그아웃·세션 복원·프로필 저장 성공·마이페이지에서 다시 "사용자 정보 수정"을 누르는 경우 모두 폐기된다.
- **데스크톱/모바일 차이**: 데스크톱은 창 안에서 "취소" 버튼(창 닫기)이 있고, 모바일 화면에는 "취소" 버튼이 없다(상단바 뒤로가기 → 마이페이지). 데스크톱 닫기 시 프로필 메뉴가 다시 열린다.

### PRF-04 사용자 정보 수정
- **대상 사용자**: 본인 확인을 통과한 로그인 사용자
- **진입 경로**: PRF-03 성공 후. 데스크톱 — 창 제목 "사용자 정보 수정"(창 안 제목 포함, 설명 현재 문구: "변경할 항목만 입력하세요. 비워 둔 항목은 기존 값이 그대로 유지됩니다."). 모바일 — `/mobile/profile/edit`
- **흐름**: 1. 변경하려는 항목만 입력/선택(이름, 새 비밀번호, 프로필 이미지 — 모두 선택 사항) 2. "변경 사항 저장" 3. 저장 중 표시 4. 성공 시 성공 배너 표시, 입력 초안 모두 초기화(이름·비밀번호·이미지 선택), 화면에 즉시 반영
- **입력 항목**:

| 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
|---|---|---|---|---|
| 프로필 이미지 | 이미지 파일 1개(이미지 종류만 선택 가능). 버튼 라벨 "프로필 이미지 선택"(이미 선택했다면 "이미지 다시 선택"). 선택하면 선택한 이미지로 즉시 미리보기 | 아니오 | 클라이언트 용량 검증 없음(서버 파일 상한은 COM-15). 안내(데스크톱만) 선택 전 "선택하지 않으면 기존 이미지가 유지됩니다." / 선택 후 "새 이미지를 저장하면 반영됩니다." | 업로드 실패 시 "업로드에 실패했어요." + "다시 시도" |
| 이름 | 텍스트(자동완성 name). 현재 이름 표시: 데스크톱 "현재 이름 · {이름}", 모바일 "현재 · {이름}". 자리표시: 데스크톱 "변경할 이름을 입력하세요", 모바일 "변경할 이름" | 아니오 | 앞뒤 공백 제거 후 비어 있으면 변경하지 않음. 안내 "변경하지 않으려면 비워 두세요." | 없음(길이 제한 검증 없음) |
| 비밀번호 변경 — 새 비밀번호 | 비밀번호, 자리표시 "변경할 비밀번호" | 아니오 | 안내(데스크톱만) "변경하지 않으려면 두 칸을 모두 비워 두세요." 복잡도·길이 검증 없음 | 확인란이 비어 있을 때: "비밀번호 확인란도 함께 입력해야 해요." |
| 비밀번호 변경 — 확인 | 비밀번호, 자리표시 "변경할 비밀번호 확인"(접근성 이름 "변경할 비밀번호 확인") | 새 비밀번호를 입력했다면 예(둘은 함께 입력/함께 비움) | 새 비밀번호와 일치해야 함 | 한쪽만 입력: "비밀번호 확인란도 함께 입력해야 해요." / 불일치: "두 비밀번호가 일치하지 않습니다." (알림 역할, 입력 오류 표시) |

- **표시 데이터**: 현재 프로필 이미지(선택 시 미리보기로 대체), 현재 이름, 결과 배너들
- **상태**:
  - 저장 버튼("변경 사항 저장") 비활성 조건: 변경 사항이 하나도 없음(이름 비어 있음, 비밀번호 두 칸 비어 있음, 이미지 미선택) / 비밀번호 검증 오류 있음 / 저장 처리 중 / 프로필 로딩 중
  - 처리 중 — 버튼 "저장 중…" + 스피너. 이미지가 있으면 이미지 영역이 "업로드 중…" + 진행 표시(이때 이미지 선택 컨트롤 숨김).
  - 성공 — 상태 알림 현재 문구: 데스크톱 "변경 사항이 저장되었어요. 프로필에 즉시 반영됩니다." / 모바일 "저장되었어요. 프로필에 즉시 반영됩니다." 데스크톱은 추가로 반영 미리보기(아바타+이름+"Header · Popover 갱신됨" 표기)를 보여준다.
  - 일반 저장 실패 — 알림 현재 문구: 데스크톱 "저장에 실패했어요. 잠시 후 다시 시도해 주세요." / 모바일 "저장에 실패했어요. 다시 시도해 주세요."
  - 이미지 업로드 실패 — 일반 실패 배너 대신 이미지 영역에 "업로드에 실패했어요." + "다시 시도"(저장 재실행). 아바타에 오류 표시.
  - 이미지는 올라갔으나 프로필 저장이 실패 — 같은 이미지를 다시 올리지 않고 이미 올라간 파일을 재사용해 다음 저장을 시도(중복 업로드 방지). 사용자에게는 일반 저장 실패 배너가 보임.
  - 비밀번호 변경 후 세션 갱신 실패 — 알림 현재 문구: "변경 사항은 저장되었지만 세션을 갱신하지 못했어요. 다시 로그인해 주세요." 이 경우 입력은 초기화되고 로그인 상태가 풀려 보호 화면 규칙(COM-04)에 따라 로그인으로 이동하게 됨.
  - 사용자가 입력을 바꾸거나 파일을 다시 고르면 이전 결과(성공/실패) 배너는 사라짐.
- **결과**:
  - 이름·이미지만 변경: 프로필 정보와 로그인 정보 이름이 즉시 갱신되어 헤더/상단바 아바타·이름에 바로 반영.
  - 비밀번호 변경: 저장 후 서버 세션 토큰을 재발급받아 로그인 유지(성공 시). 실패 시 위 세션 갱신 실패 안내.
  - 저장 성공 시 본인 확인 허용 기록은 폐기 → 같은 화면에서 계속 수정은 가능하나 화면을 벗어났다 다시 수정하려면 다시 본인 확인 필요.
  - 이후 화면 이동: 자동 이동 없음. 데스크톱은 "취소"(창 닫기), 모바일은 뒤로가기로 마이페이지.
- **정책·예외 규칙**:
  - 저장 요청은 변경된 항목만 보낸다(빈 항목은 기존 값 유지).
  - 이미지는 먼저 파일을 올린 뒤 받은 파일 ID 로 프로필을 저장하는 2단계. 서버에 업로드 파일 삭제 기능이 없어, 저장 실패 시 이미 올린 파일 ID 를 재시도에 재사용.
  - 변경 내용이 있는 동안 브라우저 탭 닫기/새로고침 시 브라우저 기본 이탈 경고를 띄운다.
  - **저장하지 않은 변경 확인 절차**(변경 사항이 있을 때): 데스크톱 — 창 닫기(취소 버튼·닫기 버튼·Esc·바깥 누르기)를 하면 확인: 제목 "저장하지 않은 변경 사항이 있어요" / 설명 "닫으면 지금까지 수정한 내용이 사라져요. 그래도 닫을까요?" / 확정 "변경 사항 버리기" / 취소 "계속 수정". 모바일 — 라우트 이동(뒤로가기·상단바 뒤로가기·하단 이동 등)을 하면 확인: 제목 "저장하지 않은 변경 사항이 있어요" / 설명 "지금 나가면 수정한 내용이 사라져요. 그래도 돌아갈까요?" / 확정 "나가기" / 취소 "계속 수정". 변경 사항이 없으면 확인 없이 닫힘/이동.
  - 모바일: 이 화면은 본인 확인 허용이 유효할 때만 열린다. 허용이 없거나 만료(5분 초과)되었거나 사용자가 다르면 `/mobile/profile/verify` 로 이동(히스토리 대체). 화면에 진입하는 즉시 허용 기록은 폐기되므로 **새로고침하면 다시 본인 확인으로 돌아간다.** 즉 모바일 수정 화면은 1회 진입권이다.
  - 데스크톱: 수정 창은 본인 확인 창에서 계속하기를 통해서만 열린다(별도 URL 없음).
- **데스크톱/모바일 차이**: 위 항목 참조 — 구조(창 vs 화면), 안내/자리표시 문구(데스크톱이 더 자세함), "취소" 버튼(데스크톱만), 반영 미리보기(데스크톱만), 이탈 확인 트리거(창 닫기 vs 라우트 이동), 새로고침 시 동작(모바일은 본인 확인으로 복귀).

### PRF-05 화면 밝기 선택
- COM-13 참조. 데스크톱은 프로필 메뉴 안, 모바일은 마이페이지 "화면" 구역.

### PRF-06 로그아웃
- COM-06 참조. 데스크톱은 프로필 메뉴 하단, 모바일은 마이페이지 최하단 버튼.

### PRF-07 데스크톱 프로필 URL 접근
- **대상 사용자**: 로그인 사용자 전체 (데스크톱)
- **진입 경로**: `/main/profile`, `/main/profile/verify`, `/main/profile/edit` 직접 접속
- **결과**: 화면 없이 `/main`(홈)으로 즉시 이동(히스토리 대체). 본인 확인/수정 창은 열리지 않는다.
- **정책·예외 규칙**: 모바일 주소를 데스크톱 기기에서 열면 모바일 화면이 그대로 열린다(COM-01 참조).
- **데스크톱/모바일 차이**: 데스크톱 전용 동작

## 데이터 필드 사전
| 필드 | 의미 | 형식/예시 | 비어 있을 수 있는지 |
|---|---|---|---|
| 아이디(username) | 로그인 아이디(변경 불가, 화면에 직접 표시하지 않음) | 문자열 | 아니오 |
| 이름(name) | 표시 이름 | 문자열 | 아니오 |
| 프로필 이미지(profileImage) | 파일 정보(파일 ID, 원본 파일명, 형식, 크기 등) | 객체, 화면은 파일 ID 의 작은 썸네일만 사용 | 예(기본 아바타) |
| 새 비밀번호 | 변경할 비밀번호(서버로만 전송, 화면 비표시) | 문자열 | 예 |
| 본인 확인 허용 | 5분 유효 수정 권한 표식 | 사용자 + 시각, 탭 단위 저장 | 만료/폐기 시 없음 |

## 기술 제약
- 프로필 조회/수정/비밀번호 확인/이미지 업로드는 서버 API 에 의존: 현재 비밀번호 확인 요청 → 일치 시 성공 응답(본문 없음), 불일치는 400 또는 401 로 구분. 이미지는 파일 업로드 후 파일 ID 로 프로필에 연결.
- 서버에 업로드 파일 삭제 기능이 없다(프로필 이미지 교체 시 이전 파일이 남을 수 있음).
- 이미지 업로드 크기 제한은 서버 기준(파일당 50MB; COM-15). 프로필 화면은 클라이언트에서 용량·형식 검증을 하지 않고 "이미지 종류"만 파일 선택 필터로 건다.
- 본인 확인 허용은 탭 단위 저장소에 저장되므로 다른 탭과 공유되지 않고 탭을 닫으면 사라진다.
- 모바일 이탈 확인은 라우터의 이동 차단 기능에 의존한다(앱이 해당 라우터 구성일 때만 동작). 데스크톱 창 닫기 확인은 별도 로직.
- 비밀번호 변경 직후 세션 토큰을 재발급받아야 로그인이 유지된다.

## 확인 필요
- 사용자 이름 외 이메일 등 다른 프로필 필드는 코드에 없음. 기획 문서에 추가 항목이 있는지 확인 필요.
- 비밀번호 정책(최소 길이·복잡도)은 클라이언트에 없고 서버 응답에 의존. 서버 거절 시에도 화면은 일반 저장 실패 문구만 보인다(구체 사유 미표시).
- 데스크톱 반영 미리보기 영역에 구현 용어("Header · Popover 갱신됨")가 사용자 문구로 노출됨 — 의미는 "상단 프로필 영역에 즉시 반영됨". 리디자인 시 문구 확정 필요.
- 모바일 수정 화면이 새로고침 시 본인 확인으로 돌아가는 것이 의도인지 확인 필요(보안상 의도로 보임).
- 이미지 업로드 실패 시 프로필 화면은 공통 업로드 오류 문구(COM-15)를 쓰지 않고 "업로드에 실패했어요." 한 가지만 보임.
- 성공 시 화면 이탈이 자동으로 일어나지 않아 사용자가 직접 돌아가야 함. 의도 확인 필요.
