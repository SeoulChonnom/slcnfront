# 여행

## 개요
사용자는 다녀온 여행을 기간(시작일~종료일) 단위로 기록하고 다시 열람한다. 한 건의 여행은 제목·지역·기간·대표 사진·날짜별 방문 장소(장소명, 카테고리, 메모)·사진 앨범·태그로 구성된다. 목록에서 여행을 찾아보고(검색), 상세에서 읽고, 등록·수정 화면에서 입력한다.

**확정된 제품 정책 (필수 준수)**: 여행 상세는 **읽기 전용**이다. 장소·사진·태그의 추가/삭제/편집 기능을 상세 화면에서 제공하지 않으며, 모든 편집은 수정 화면으로 일원화한다. 여행 기록 삭제도 수정 화면에 둔다(현재 구현 여부는 "확인 필요" 참조). 상세 화면의 빈 상태 문구도 "여행 수정에서 …" 로 수정 화면으로 안내한다.

## URL
| 경로 (/main, /mobile 공통 뒤쪽) | 화면 의미 | 접근 권한 | 비고 |
|---|---|---|---|
| `travel` | 여행 기록 목록 | 로그인 사용자 | 미로그인 시 해당 기기 로그인 화면으로 이동(복귀 경로 보존) |
| `travel/register` | 새 여행 등록 | 로그인 사용자 | 모바일은 "상세형" 화면 틀(상단 제목 "새 여행" + 뒤로가기) |
| `travel/:id` | 여행 상세(읽기 전용) | 로그인 사용자 | 모바일 상단 제목 "여행", 목록 계열 화면 틀 |
| `travel/:id/edit` | 여행 수정 | 로그인 사용자 | 모바일은 상세형 화면 틀(상단 제목 "여행 수정" + 뒤로가기, 취소/뒤로는 목록으로 이동) |

## 기능 목록

### TRV-01 여행 목록 보기
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 여행 메뉴(`travel`), 등록/수정 취소, 상세의 "여행 목록" 버튼
- **흐름**: 1. 진입 시 전체 여행 목록을 한 번에 불러온다. 2. 시작 연도별로 묶어 "YYYY년" 소제목 아래에 나열한다(서버가 최신순으로 내려주며, 그 순서를 유지한 채 연도로만 묶음). 3. 여행 항목을 누르면 해당 여행 상세로 이동한다.
- **표시 데이터** (항목당): 대표 사진(없거나 불러오기 실패 시 사진 없음 상태), "N박 M일", 지역, 기간("YYYY.MM.DD – YYYY.MM.DD"), 제목, 한 줄 평(있을 때만), 태그 목록("#태그", 있을 때만)
- **상태**
  - 로딩: 목록 자리에 로딩 표시(항목 2개 분량의 자리표시)
  - 에러: 현재 문구: "여행 기록을 불러오지 못했어요." + 다시 시도 동작
  - 빈 상태(등록된 여행 0건): 현재 문구: 제목 "아직 남긴 여행이 없어요." / 설명 "같이 다녀온 여행을 날짜별로 기록할 수 있어요." / 동작 "새 여행 기록하기"(등록 화면 이동)
  - 검색 결과 없음: 현재 문구: 제목 "검색 결과가 없어요." / 설명 "다른 이름이나 지역으로 찾아보세요."
- **결과**: 항목 선택 시 상세 이동
- **정책·예외 규칙**: 페이지네이션·정렬 선택·필터(태그/지역/연도 선택)는 없다. 연도 구분은 단순 그룹 표시이며 접기/이동 기능 없음. 화면 제목: "여행 기록".
- **데스크톱/모바일 차이**: 없음(기능 동일)

### TRV-02 여행 검색
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 목록 상단의 검색 입력
- **흐름**: 1. 검색어를 입력한다. 2. 입력과 동시에(서버 재조회 없이) 이미 불러온 목록에서 걸러 보여준다. 3. 검색어를 지우면 전체가 다시 보인다.
- **입력 항목**
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 여행 검색 | 자유 텍스트 (안내문구: "날짜 · 여행 이름 · 지역으로 검색", 접근성 라벨 "여행 검색") | 아니오 | 앞뒤 공백 제거, 대소문자 무시, 부분 일치 | 없음 |
- **표시 데이터**: 검색 대상 필드는 제목, 지역, 기간 표기 문자열("YYYY.MM.DD – YYYY.MM.DD"), 태그 이름. 이 필드들을 이어 붙인 문자열에서 부분 일치하면 노출.
- **상태**: 결과 0건이면 TRV-01의 "검색 결과가 없어요." 상태. 검색 중에도 연도별 묶음은 유지.
- **결과**: 목록 즉시 갱신(화면 이동 없음, 주소 변화 없음 — 새로고침 시 검색어 유지 안 됨)
- **정책·예외 규칙**: 한 줄 평은 검색 대상이 아니다.
- **데스크톱/모바일 차이**: 없음

### TRV-03 새 여행 등록 시작
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 목록 상단의 "+ 새 여행 기록하기" 버튼, 빈 상태의 "새 여행 기록하기" 동작
- **흐름**: 등록 화면(TRV-05)으로 이동
- **결과**: `travel/register` 이동
- **데스크톱/모바일 차이**: 없음

### TRV-04 여행 상세 보기 (읽기 전용)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 목록 항목 선택, 등록/수정 저장 성공 후 자동 이동
- **흐름**: 1. 상단 동작: "‹ 여행 목록"(목록으로 이동, 로딩/에러 중에도 항상 제공), "여행 수정"(데이터가 있을 때만, 수정 화면으로 이동). 2. 요약 영역: 대표 사진, "N박 M일", 지역, 기간, 제목, 한 줄 평(있을 때). 3. 섹션 순서: 날짜별 기록 → 사진 앨범 → 여행 후기 → 태그.
- **표시 데이터**
  - 요약: 대표 사진(없거나 로드 실패 시 지도 모양 대체 표시), 박/일 수, 지역, 기간, 제목, 한 줄 평
  - 날짜별 기록: 각 날짜마다 "N일차", "MM.DD · 요일(일월화수목금토)", 날짜 제목(있을 때), 날짜 메모(있을 때), 장소 목록. 장소마다 카테고리 아이콘, 장소명, 카테고리 라벨, 메모(장소 설명이 있으면 설명, 없으면 메모), 장소에 연결된 사진 썸네일(있을 때)
  - 사진 앨범: 아래 TRV-04a
  - 여행 후기: 한 줄 요약, 좋았던 점, 아쉬운 점, 다시 가고 싶은 곳, 최종 후기 — 값이 있는 항목만 표시
  - 태그: "#태그" 목록
- **상태**
  - 로딩: 본문 자리에 로딩 표시(상단 동작 중 "여행 목록"은 유지)
  - 에러/데이터 없음: 현재 문구: "여행을 불러오지 못했어요." + 다시 시도 동작
  - 날짜별 기록 없음: 현재 문구: "아직 날짜별 기록이 없어요. 여행 수정에서 남겨 보세요."
  - 날짜에 장소 없음: 현재 문구: "이 날 기록한 장소가 없어요."
  - 사진 없음: 현재 문구: "아직 사진이 없어요. 여행 수정에서 사진을 올릴 수 있어요."
  - 후기 없음(모든 후기 항목이 비어 있음): 현재 문구: "아직 여행 후기가 없어요."
  - 태그 없음: 현재 문구: "아직 태그가 없어요. 여행 수정에서 태그를 붙일 수 있어요."
  - 개별 사진 로드 실패: 사진 없음과 같은 대체 표시(깨진 이미지 노출 금지)
- **결과**: "여행 수정" → TRV-07, "여행 목록" → TRV-01
- **정책·예외 규칙**: **읽기 전용 — 이 화면에서 장소/사진/태그/후기의 추가·삭제·편집 컨트롤을 두지 않는다. 여행 삭제 컨트롤도 상세에 두지 않는다.** 사진 클릭 시 확대 보기/라이트박스 같은 기능은 현재 없다(캡션은 접근성 라벨로만 사용, 캡션 없으면 "여행 사진"/"장소 사진").
- **데스크톱/모바일 차이**: 없음(기능 동일)

### TRV-04a 사진 앨범 보기 방식 전환
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 상세의 사진 앨범 섹션 (사진이 1장 이상일 때만 전환 수단 제공)
- **흐름**: 1. 보기 방식 3종 중 선택: "전체"(기본) / "날짜별" / "장소별". 2. "전체": 모든 사진 나열. 3. "날짜별": "N일차 · YYYY.MM.DD" 소제목별로 묶음, 날짜에 연결되지 않은 사진은 "날짜 없는 사진". 4. "장소별": 장소명별로 묶음, 연결 안 된 사진은 "장소 없는 사진". 5. 사진이 없는 묶음은 표시하지 않는다.
- **상태**: 사진 0장이면 전환 수단 없이 TRV-04의 "아직 사진이 없어요…" 문구만 표시
- **정책·예외 규칙**: 선택 상태는 화면 내 임시 상태(새로고침 시 "전체"로 복귀). 키보드(좌/우 화살표, Home, End)로 보기 방식 이동 가능해야 함.
- **데스크톱/모바일 차이**: 없음

### TRV-05 새 여행 등록 (한 화면 폼)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: TRV-03
- **흐름**: 1. 화면 제목 "새 여행 기록하기", 안내 "기본 정보를 입력하면 날짜별 기록 칸이 자동으로 만들어져요." (모바일은 상단 바에 제목이 있으므로 화면 내에는 안내문만, 데스크톱은 "‹ 돌아가기" 동작 포함). 2. 기본 정보 입력(TRV-06a). 3. 대표 사진 선택(TRV-06b). 4. 날짜별 기록 입력(TRV-06c). 5. 사진 앨범 선택(TRV-06d). 6. 태그 입력(TRV-06e). 7. "저장하기" 제출. 8. 입력 검증 실패 시 첫 오류 항목으로 포커스 이동(제목 → 지역 → 시작일 → 종료일 → 대표 사진 → 날짜별 기록 오류 순). 9. 사진이 있으면 먼저 업로드, 이어서 여행 저장. 10. 성공 시 해당 여행 상세로 이동.
- **입력 항목**
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 제목 | 텍스트 (예시 "예) 봄여행") | 예 | 공백만 입력 불가 | "제목을 입력해 주세요." |
  | 지역 | 텍스트 (예시 "예) 경주") | 예 | 공백만 입력 불가 | "지역을 입력해 주세요." |
  | 시작일 | 날짜 선택 | 예 | 비어 있으면 안 됨 | "시작일을 선택해 주세요." |
  | 종료일 | 날짜 선택 | 예 | 비어 있으면 안 됨, 시작일보다 앞서면 안 됨(같은 날은 허용 = 당일치기) | "종료일을 선택해 주세요." / "종료일은 시작일 이후여야 해요." |
  | 여행 기간 | 증감 조작(−/+) | — | TRV-06a 참조 | — |
  | 대표 사진 | 이미지 1장 | 등록 시 예 / 수정 시 아니오 | jpg·jpeg·png, 50MB 이하 | "대표 사진을 등록해 주세요." (파일 형식/용량 오류는 TRV-06b) |
  | 날짜별 장소 | 날짜마다 0개 이상 | 아니오 | 장소명 없이 메모만 적은 장소가 있으면 저장 불가 | "N일차[, M일차…]에 메모만 적고 장소명을 비워 둔 곳이 있어요. 장소명을 입력해 주세요." |
  | 사진 앨범 | 이미지 여러 장 | 아니오 | jpg·jpeg·png, 장당 50MB 이하 | TRV-06d |
  | 태그 | 텍스트 여러 개 | 아니오 | TRV-06e | — |
- **표시 데이터**: 입력 폼 전체, 섹션 보조 문구(아래 각 기능 참조)
- **상태**
  - 처리 중: 제출 버튼 비활성+진행 표시. 사진 업로드 단계 현재 문구 "사진 올리는 중…", 저장 단계 "저장 중…". 처리 중에는 "취소"도 비활성.
  - 업로드 실패: 폼 하단 오류 알림, 입력 내용은 그대로 유지. 현재 문구: 용량 초과(서버 413) "사진 용량이 너무 커서 올리지 못했어요. 50MB 이하 사진으로 다시 시도해 주세요." / 네트워크 오류 "사진을 올리지 못했어요. 네트워크 연결을 확인해 주세요." / 서버 메시지가 있으면 "사진을 올리지 못했어요. {서버 메시지}" / 그 외 "사진을 올리지 못했어요. 잠시 뒤 다시 시도해 주세요."
  - 저장 실패: 폼 하단 오류 알림에 서버 메시지 표시(없으면 "저장 중 오류가 발생했어요. 다시 시도해 주세요."), 입력 내용 유지. 제출 오류가 생기면 해당 알림으로 포커스 이동.
  - 성공: 상세 이동
- **결과**: 목록 캐시 갱신, 임시저장 삭제, 새 여행 상세로 이동
- **정책·예외 규칙**
  - 장소명이 빈 장소 행은 저장 시 제외된다(메모만 있는 경우는 위 검증으로 막음).
  - 장소 카테고리 미선택 시 "기타"로 저장.
  - 장소 메모는 앞뒤 공백 제거, 비면 저장하지 않음.
  - 한 줄 평·좋았던 점 등 후기 항목과 날짜별 제목/메모, 장소 주소, 날짜·장소별 사진 입력은 **이 폼에 없다**(상세 표시용 데이터는 있으나 입력 수단 없음 — 확인 필요).
  - 날짜별 대표 사진은 폼 데이터 구조에만 있고 화면 입력 수단이 없다.
- **데스크톱/모바일 차이**: 데스크톱은 화면 내에 "‹ 돌아가기" 동작과 제목·안내를 표시. 모바일은 화면 틀(상단 바)이 제목과 뒤로가기를 담당하며 화면 내에는 안내문만 표시(제목은 화면 낭독용으로만 존재). 폼 기능은 동일.

### TRV-06a 기본 정보·기간 조정
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 등록/수정 폼 상단
- **흐름**: 1. 시작일·종료일을 선택하면 그 기간의 모든 날짜가 "N일차" 입력 칸으로 자동 생성된다. 2. 이미 입력한 날짜 칸은 날짜가 범위에 남아 있는 한 내용이 보존되고, 새로 포함된 날짜만 빈 칸이 추가된다. 3. "여행 기간" 증감 조작: "+"(라벨 "여행 기간 늘리기")는 종료일을 하루 뒤로(종료일이 비어 있으면 시작일 다음 날), "−"(라벨 "여행 기간 줄이기")는 종료일을 하루 앞으로 당긴다. 4. 현재 기간 표시: "N박 M일", 0박이면 "당일치기", 계산 불가 시 "—". 5. 안내 문구: "늘리면 하루가 늘고, 줄이면 마지막 날이 빠져요."
- **상태/제약**: "+"는 시작일이 없으면 비활성. "−"는 기간 계산이 불가하거나 당일치기(0박)면 비활성. 종료일이 시작일보다 앞서거나 한쪽이 비면 날짜 칸이 없음.
- **정책·예외 규칙 (데이터 손실 확인 절차)**: 시작일/종료일 변경 또는 "−"로 인해 **내용(장소명·장소 메모·날짜별 사진 중 하나)이 있는 날이 범위 밖으로 빠질 때**, 화면 이동 없이 확인 절차를 거친다. 빈 날짜 칸만 빠지는 경우는 확인 없이 진행. 현재 문구: 제목 "날짜를 바꿀까요?" / 본문 "{N일차(YYYY.MM.DD), …}에 적은 기록이 사라져요. 계속할까요?" / 확정 동작 "그래도 바꾸기" / 취소 동작(취소). 취소하면 날짜 변경이 적용되지 않는다.
- **데스크톱/모바일 차이**: 없음

### TRV-06b 대표 사진 선택
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 등록/수정 폼의 "대표 사진" 섹션 (등록 시 필수 표시 *)
- **흐름**: 1. 끌어다 놓기 또는 파일 선택으로 이미지 1장 지정. 2. 형식 검사 → 용량 검사 순으로 통과해야 폼에 반영된다. 3. 지정한 파일은 해제(비우기) 가능. 4. 실패한 선택은 폼에 반영되지 않고 오류만 표시된다.
- **표시 데이터**: 섹션 제목 "대표 사진 *", 보조 문구 "여행 목록과 상세 상단에 보이는 대표 이미지예요. 반드시 등록해야 저장할 수 있어요.", 안내 "대표 사진을 끌어다 놓거나 선택하세요", 힌트 "PNG · JPG · 최대 50MB"
- **입력 항목**
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 대표 사진 | 이미지 파일 1개 | 등록 시 예 | 확장자 jpg/jpeg/png 및 MIME(image/jpeg, image/png; MIME이 비어 있는 경우는 허용), 50MB 이하 | "jpg, jpeg, png 형식의 사진만 올릴 수 있어요." / "사진은 50MB까지 올릴 수 있어요." / 미선택 제출 시 "대표 사진을 등록해 주세요." |
- **정책·예외 규칙**: 끌어다 놓기도 선택과 동일한 형식·용량 검사를 거친다. **수정 화면에서 기존 대표 사진은 화면에 표시되지 않으며** 새 파일을 고르면 기존 대표 사진을 교체한다(고르지 않으면 유지).
- **데스크톱/모바일 차이**: 없음 (끌어다 놓기는 데스크톱 중심, 선택은 공통)

### TRV-06c 날짜별 장소 기록 (장소 추가·편집·삭제·카테고리)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 등록/수정 폼의 "날짜별 기록" 섹션. 시작일·종료일이 정해지면 날짜별 카드가 생성됨
- **흐름**: 1. 섹션 제목 "날짜별 기록", 우측 "총 N일"(1일 이상일 때). 보조 문구 "날짜별로 방문한 장소와 기억을 기록해 주세요." 2. 날짜 칸이 없을 때 안내: 현재 문구 "시작일과 종료일을 입력하면 날짜별 기록 카드가 자동으로 생성돼요." 3. 각 날짜 카드는 "N일차"와 "YYYY.MM.DD" 표시. 4. "+ 장소 추가"로 빈 장소 행 추가(순서는 추가 순, 번호 1부터 표시). 5. 장소 행마다 장소명, 카테고리 선택, 메모 입력, "장소 삭제"(접근성 라벨, 즉시 삭제·확인 절차 없음). 6. 한 날짜에 장소를 0개 둘 수 있다.
- **입력 항목**
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 장소명 | 텍스트 (예시 "예) 경복궁", 접근성 라벨 "장소명") | 아니오(단, 메모를 쓰면 필수) | 장소명이 비고 메모만 있으면 저장 불가. 둘 다 비면 저장 시 그 행은 무시 | "N일차에 메모만 적고 장소명을 비워 둔 곳이 있어요. 장소명을 입력해 주세요." |
  | 카테고리 | 단일 선택, 같은 값을 다시 누르면 해제 | 아니오 | 관광지 / 음식점 / 카페 / 숙소 / 쇼핑 / 이동 / 체험 / 기타 (8종). 미선택 시 "기타"로 저장 | 없음 |
  | 메모 | 텍스트 (예시 "예) 노을이 예뻤어요", 접근성 라벨 "메모") | 아니오 | 앞뒤 공백 제거 | 없음 |
- **상태**: 장소 관련 오류 알림은 섹션 상단에 표시되며 제출 시도 후 포커스가 이동한다. 사용자가 장소명을 채워 해소하면 오류는 자동으로 사라진다.
- **정책·예외 규칙**: 장소 주소 입력·지도 검색·장소 순서 변경(드래그)·장소별 사진 첨부는 없다. 장소의 저장 순서는 화면 순서. 수정 시 기존 장소의 메모 칸에는 "장소 설명이 있으면 설명, 없으면 메모"가 채워진다(저장 시에는 메모로 전송).
- **데스크톱/모바일 차이**: 없음

### TRV-06d 사진 앨범 선택
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 등록/수정 폼의 "사진 앨범" 섹션
- **흐름**: 1. 끌어다 놓기 또는 선택으로 여러 장 지정. 2. 다시 지정하면 직전 선택 목록을 대체한다(누적 아님). 3. 우측에 "N장"(1장 이상일 때). 보조 문구 "여행에서 찍은 전체 사진을 올려 주세요." 안내 "사진을 끌어다 놓거나 선택하세요", 힌트 "PNG · JPG · 여러 장 선택 가능"
- **입력 항목**
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 사진 앨범 | 이미지 여러 장 | 아니오 | 장당 jpg/jpeg/png, 50MB 이하. 장수 상한 없음. 규격에 맞지 않는 파일은 제외하고 나머지만 반영 | 첫 번째 위반의 문구만 표시: "jpg, jpeg, png 형식의 사진만 올릴 수 있어요." / "사진은 50MB까지 올릴 수 있어요." |
- **정책·예외 규칙**: 업로드는 요청당 파일 6장·누적 약 100MB 단위로 나누어 순서대로 올린다. 새로 올린 앨범 사진은 기존 앨범 사진 뒤에 붙는다. **수정 화면에서 기존 앨범 사진은 목록으로 보이지 않고, 개별 삭제·순서 변경도 불가능**하다(새 사진 추가만 가능). 선택 파일 목록 개별 제거 수단의 유무는 확인 필요.
- **데스크톱/모바일 차이**: 없음

### TRV-06e 태그 추가·삭제
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 등록/수정 폼의 "태그" 섹션
- **흐름**: 1. 보조 문구 "여행을 나타내는 키워드를 추가해 보세요. (예: 봄여행, 부부여행)". 2. 입력 칸(예시 "예) 봄여행", 접근성 라벨 "태그 추가")에 쓰고 "추가" 또는 Enter로 추가(Enter가 폼 제출로 이어지지 않아야 함). 3. 추가된 태그는 "#태그"로 나열되며 각각 삭제 가능(접근성 라벨 "{태그} 태그 삭제").
- **입력 항목**
  | 항목 | 형식 | 필수 | 제약·검증 | 현재 에러 문구 |
  |---|---|---|---|---|
  | 태그 | 텍스트 | 아니오 | 앞뒤 공백 제거, 맨 앞 "#" 제거, 빈 값 무시, 중복 무시(입력칸만 비움), 개수·길이 제한 없음 | 없음 |
- **결과**: 저장 시 태그 이름 배열 전체가 전송되어 서버의 태그 목록을 대체
- **데스크톱/모바일 차이**: 없음

### TRV-06f 작성 중 임시저장 복원 (등록 화면만)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 등록 화면 진입 시, 이전에 작성하다 저장 없이 나간 내용이 브라우저에 남아 있을 때
- **흐름**: 1. 폼 상단에 안내 표시. 현재 문구: "작성하던 내용이 남아 있어요." (선택한 대표 사진/앨범 사진이 있었으면 이어서 " 대표 사진 · 사진 앨범 (N장) 파일은 다시 선택해 주세요."). 2. "이어서 쓰기": 제목·지역·기간·날짜별 장소·태그를 복원한다(사진 파일은 복원 불가). 3. "새로 쓰기": 임시저장을 버리고 빈 폼으로 시작. 4. 어느 쪽도 고르지 않으면 폼은 빈 상태 그대로 유지(자동 적용 없음).
- **정책·예외 규칙**: 등록 화면에서만 동작하며 수정 화면에서는 임시저장하지 않는다. 입력이 하나라도 있으면 값이 바뀔 때마다 자동 저장되고, 저장 성공 시 삭제된다. 브라우저 탭/세션 범위에서만 유지된다(탭을 닫으면 소멸). 저장소를 쓸 수 없는 환경에서는 조용히 임시저장 없이 동작.
- **데스크톱/모바일 차이**: 없음

### TRV-07 여행 수정
- **대상 사용자**: 로그인 사용자 전체(본인 소유 여부 제한은 코드상 없음 — 서버 판단)
- **진입 경로**: 상세의 "여행 수정" 버튼
- **흐름**: 1. 화면 제목 "여행 수정", 안내 "기본 정보를 수정하면 날짜별 기록 칸이 자동으로 조정돼요." 2. 기존 여행 정보를 불러온 뒤에 폼이 나타난다(제목, 지역, 기간, 날짜별 장소[이름·카테고리·메모], 태그가 채워짐). 3. 등록과 동일하게 편집(TRV-06a~06e). 4. "수정하기"로 제출. 5. 새 파일을 골랐다면 업로드 후 저장. 6. 성공 시 상세로 이동.
- **입력 항목**: 등록(TRV-05)과 동일. 차이: 대표 사진 필수 아님(새로 고르지 않으면 기존 유지).
- **상태**
  - 로딩: 현재 문구 "불러오는 중…" (폼은 아직 안 보임)
  - 불러오기 실패: 현재 문구 "여행 정보를 불러오지 못했어요. 여행 목록에서 다시 열어 주세요." (이 경우 폼은 표시되지 않음 — 다시 시도 동작 없음)
  - 처리 중/업로드 실패/저장 실패: TRV-05와 동일하되 제출 라벨은 "수정하기"
- **결과**: 목록·해당 상세 캐시 갱신, 해당 여행 상세로 이동
- **정책·예외 규칙**
  - 모든 편집(장소·사진·태그·기간)은 이 화면에서만 가능하다(상세는 읽기 전용).
  - 수정은 전체 교체 방식: 화면에 보이는 날짜별 장소·태그가 서버 저장본을 대체한다. 기간 변경으로 날짜가 줄어들면 해당 날짜의 기록이 삭제된다(저장 시 삭제 동의가 항상 함께 전송됨). 날짜가 줄어드는 경우의 화면 내 확인은 TRV-06a(내용 있는 날만).
  - 기존 사진(대표 외 앨범·날짜·장소 연결 사진)은 저장 시 그대로 유지된다. 새 대표 사진을 고르면 기존 대표만 교체된다.
  - 취소: 목록으로 이동(상세가 아님). 수정 내용 임시저장 없음.
- **데스크톱/모바일 차이**: TRV-05와 동일 (제목 표시 위치만 다름)

### TRV-08 취소 / 뒤로가기 (등록·수정)
- **대상 사용자**: 로그인 사용자 전체
- **진입 경로**: 폼 하단 "취소", 데스크톱 화면 내 "‹ 돌아가기", 모바일 상단 바 뒤로가기
- **흐름**: 확인 절차 없이 여행 목록으로 이동한다.
- **정책·예외 규칙**: 작성 중 내용 유실 경고 없음(등록은 임시저장으로 복원 가능, 수정은 유실). 제출 처리 중에는 폼 하단 "취소"가 비활성(상단 뒤로가기는 별도).
- **데스크톱/모바일 차이**: 있음 — 데스크톱은 "돌아가기"와 "취소" 두 곳, 모바일은 상단 바 뒤로가기와 "취소"

### TRV-09 여행 삭제
- **상태: 현재 화면에서 제공되지 않음 (미구현)**
- 삭제 서버 연동(여행 한 건 삭제 요청)과 삭제 후 목록 캐시 갱신 로직은 준비돼 있으나 어떤 화면에도 연결되어 있지 않다.
- **확정 정책**: 삭제는 **수정 화면**에 둔다. 상세·목록에는 삭제를 두지 않는다. 리디자인 시 수정 화면에 삭제 진입점과 삭제 확인 절차(되돌릴 수 없음을 알리는 별도 단계)가 필요하며, 삭제 성공 후에는 여행 목록으로 이동하고 목록이 갱신되어야 한다. 삭제 실패 시 수정 화면에 오류가 표시되고 입력 내용은 유지되어야 한다. (현재 문구는 없음 — 신규 작성 필요)

## 기술 제약
- 사진 형식은 jpg, jpeg, png만 허용. 장당 50MB 한도. 업로드는 서버 한도(요청 전체 약 110MB) 때문에 6장·약 100MB 단위로 순차 분할 업로드된다. 앨범 장수 상한은 없음.
- 사진 파일은 먼저 업로드하고 반환된 파일 식별자로 여행 저장을 호출하는 2단계 구조(업로드 후 저장 실패 시 업로드된 파일이 남을 수 있음).
- 여행 목록은 단일 호출로 전체를 받고 검색은 클라이언트 측 필터이며 서버 페이지네이션이 없다. 여행이 많아지면 한 번에 모두 렌더링된다.
- 날짜별 칸은 시작일~종료일로 자동 생성되며 날짜를 사용자가 임의로 추가/삭제할 수 없다.
- 날짜 입력은 브라우저 기본 날짜 선택 컨트롤(type=date)을 사용 중이며, 값은 YYYY-MM-DD.
- 임시저장은 브라우저 세션 저장소(탭 단위)이며 파일은 저장하지 못한다.
- 수정 저장은 서버에서 날짜별 기록·태그·파일 목록을 통째로 교체하는 방식. 기존 사진은 식별자와 함께 되돌려 보내야 유지된다.
- 사진 이미지는 상황별 크기 변형(대표/목록/썸네일)을 서버가 제공하는 주소 규칙으로 받아온다.
- 지도 SDK(카카오 지도)·주소 검색·도보 경로 기능(위치 정보/브라우저 위치 권한 포함)은 코드베이스의 별도 "나들이/점검" 영역에서만 쓰이며 **여행 화면은 사용하지 않는다**.

## 확인 필요
1. **삭제 미구현**: 여행 삭제를 호출하는 화면이 없다(서버 연동 로직만 존재). 정책상 수정 화면에 둘 예정이나 현재 코드에는 없음. `docs/travel-feature.md` 도 "UI 미연동"으로 기록.
2. **한 줄 평·후기·날짜 제목/메모·장소 주소·장소/날짜 사진 입력 수단 없음**: 상세/목록은 이 값들을 표시하지만 등록·수정 폼에는 입력칸이 없고, 저장 시 후기는 항상 빈 객체로 전송된다. 수정 저장이 기존 후기·한 줄 평·날짜 제목/메모를 지우는지 여부는 서버 동작에 달려 있어 코드만으로 확정 불가(데이터 손실 위험 가능). 기획 문서(travel-feature)는 후기·장소별 사진 편집 등을 언급하나 현재 코드에 해당 화면은 없음.
3. **수정 시 기존 장소 식별**: 수정 폼은 기존 장소의 식별자(장소 키)를 보내지 않아, 저장 시 장소가 새로 만들어지고 장소에 연결돼 있던 사진 연결이 유지되는지는 서버 동작에 의존. 기존 장소 주소·설명도 폼에서 보존되지 않는다.
4. **수정 화면에서 기존 사진 비노출**: 기존 대표/앨범 사진을 폼에서 볼 수도, 삭제·교체 순서 조정도 할 수 없다(새 대표 교체와 앨범 추가만 가능). 사진 삭제 수단이 앱 어디에도 없음.
5. **수정 불러오기 실패 시** 다시 시도 동작이 없고 안내 문구만 표시(상세와 다름).
6. **앨범 선택 목록 표시**: 선택한 사진의 개별 해제·미리보기 지원 여부는 공통 파일 선택 컴포넌트에 달려 있어 이번 조사에서 확정하지 않음(대표 사진은 해제 가능).
7. **접근 권한**: 라우트 가드로 로그인만 요구하며, 여행 소유자/공유 개념 및 관리자 전용 제한은 코드에서 확인되지 않음.
8. **목록 정렬**: 서버 반환 순서(최신순 전제)에 의존하며 화면에서 정렬을 바꿀 수 없음. 서버 순서가 바뀌면 연도 묶음이 비연속으로 나타날 수 있음.
9. 박/일 표기: 목록·상세는 "0박 1일" 형태이고 등록 폼의 기간 조작부만 "당일치기" — 표기 통일 여부 미정.
10. 등록 폼에 전송 중이 아닐 때 페이지 이탈 경고(브라우저 이탈 확인)는 없음.
11. 제목/지역/태그/메모 글자 수 제한은 프론트에 없음(서버 제한은 확인하지 못함).
