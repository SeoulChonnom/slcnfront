# Design Specificity Verdict

**LLM 평가**: 이 앱은 카피만 바꾸면 재사용 가능한 완전 제네릭 템플릿은 아니다. `/main/map`의 [퀴즈 풀기 → 정답 시 잠금 해제 → "그날 남겨 둔 말" 공개 → 지도 이동] 흐름은 두 사람의 공유 기억을 게임화한 진짜 제품 고유 인터랙션이며, 오답 시에도 처벌 없이 다정한 카피를 쓴다. `/main/shoesRecom`의 캡션("발 편한건 역시 뉴발란스지~")은 마케팅 톤이 아니라 실제 한 사람의 말투다. `/main/travel/TRAVEL-0001`의 일차별 카드 + 좋았던 점/아쉬운 점 구조는 리스팅형이 아닌 일기형 정보구조다. 반대로 앱의 "크롬"(플로팅 헤더, 프로필 팝오버, 모바일 하단 탭바)은 반투명 유리 효과를 실제 콘텐츠 위에 검증 없이 얹어, 텍스트가 자기 자신의 배경과 충돌하는 지점까지 갔다. 그리고 그 검증 없음이 콘텐츠 그리드까지 번져, `TripCard`가 시각적으로는 `TravelCard`와 동일한 문법(헤어라인 테두리, 라운드 코너, 흰 서피스)을 쓰면서 실제로는 아무 반응도 하지 않는 "죽은 카드" — 제네릭 대시보드가 가장 흔히 실패하는 그 패턴 — 가 되어버렸다. 결론: 콘텐츠 화면은 제품 고유성이 뚜렷하지만, 크롬·플러밍 레이어는 검증되지 않은 장식(유리 효과)과 방치된 상호작용(죽은 카드)이라는 전형적인 AI-UI 실패 패턴으로 후퇴한다.

**결정적 근거(교차 확인)**: LLM 리뷰가 지목한 "Seoul Glass 크롬이 자기 콘텐츠와 충돌한다"는 판단은 디텍터가 독립적으로 잡아낸 `gpt-thin-border-wide-shadow`(1px 테두리 + 넓은 blur 그림자) 패턴과 정확히 겹친다 — 이 규칙이 `/main/map`, `/main/calendar`, `/main/shoesRecom`, `/mobile/calendar`의 헤더·하단 내비 **네 곳 모두**에서 동일하게 발생해, 한 화면의 우연이 아니라 반복되는 시스템적 습관임을 정량적으로 확인시켜준다. `cream-palette`(웜페이퍼 배경)는 DESIGN.md가 명시적으로 채택한 정체성이므로 명백한 오탐으로 처리한다. `dark-glow`는 라이트 테마 5개 페이지 전부에서 "다크 배경 위 글로우"라고 잡혔지만 `getComputedStyle(document.body).backgroundColor`가 실제로는 밝은 크림색(`rgb(255,248,248)`)이었다 — 라벨과 실제 배경이 모순되어 오분류로 판단하되, 근본 CSS(헤더 그림자에 브랜드 컬러를 섞은 `box-shadow`)는 위 `gpt-thin-border-wide-shadow`와 동일 지점이라 이중 계산일 뿐 별개의 새 문제는 아니다. `repeating-stripes-gradient`는 추가 조사가 없어 실제/오탐 여부를 확정하지 못했다 — 미확정으로 남긴다. 다크 테마에서 검출된 `low-contrast`(1.6:1 white-on-#cfcecf 퀴즈 배지)와 `text-occlusion`(카드 내부 "퀴즈 풀기" CTA가 썸네일에 가려 안 보임)은 계산된 스타일과 DOM 좌표로 재확인된 실제 버그로, LLM 리뷰가 "약간의 대비 저하"로만 인상 평가했던 지점을 수치로 확정했다. 반면 `/mobile/calendar`의 또 다른 `text-occlusion`("hairline border with w...")은 디텍터 자신이 그린 오버레이 배너 텍스트를 재스캔한 자기참조 오탐으로 확인, 제외했다.

**시각 오버레이**: 브라우저 주입(`addScriptTag` 방식)은 실제로 성공해 5개 페이지 모두에서 실제 findings를 받았다(콘솔에 규칙명이 스타일링된 로그로 출력됨 확인). 다만 검증 세션이 이미 종료되어 지금 이 순간 사용자 브라우저에 떠 있는 지속 오버레이는 없다 — 스크린샷과 위 findings 텍스트가 증거다.

# Overall Impression

콘텐츠(퀴즈, 신발 캡션, 여행 일기)는 진짜 이 커플을 위해 설계됐다는 확신이 든다. 하지만 그 콘텐츠를 감싸는 크롬 — 유리 효과 헤더/팝오버/탭바, 그리고 나들이 카드의 상호작용 — 은 검증 없이 얹힌 장식과 방치된 기본 동작이라는, 가장 흔한 AI-생성 UI의 실패 지점 그대로다. 가장 큰 기회는 크롬을 콘텐츠 수준으로 끌어올리는 것: 유리 표면의 불투명도/블러를 실제 콘텐츠에 맞게 재보정하고, 나들이 카드에 최소한의 진짜 상호작용(포커스 가능·클릭 가능한 무언가)을 부여하는 것 두 가지만으로 점수 밴드가 한 단계 올라갈 수 있다.

# What's Working

1. **퀴즈 언락 리빌, `/main/map` 퀴즈 모달 성공 상태** — 자물쇠 아이콘 전환, "그날 남겨 둔 말" 개인 메모 공개, "지도 보러가기" CTA가 함께 만드는 작은 의식(ritual). 무관한 제품이 그대로 가져다 쓸 수 없는, 설계 고유성의 가장 강한 증거.
2. **프로필 수정 재인증 플로우, `/mobile/profile/verify` → `/mobile/profile/edit`** — 자물쇠 아이콘, 평이한 설명 문구, 비밀번호 표시 토글, 유효할 때까지 비활성인 하단 고정 제출 버튼. 고위험 액션에 대한 점진적 노출·오류 예방의 교과서적 구현이며 모바일 엄지 영역에도 맞춰져 있다.
3. **여행 상세 일차별 구조, `/main/travel/TRAVEL-0001`** — Day N 카드별 빈 상태("이 날의 장소를 추가해 보세요"), 전체/날짜별/장소별 세그먼트 필터, 좋았던 점/아쉬운 점 리뷰 카드. 리스팅이 아니라 일기의 정보구조이며 DESIGN.md가 표방하는 "사진·글이 화면을 지배한다"는 원칙에 실제로 부합하는 몇 안 되는 화면.

# Priority Issues

**[P0] `/main/map`의 나들이 카드가 사실상 죽은 카드 — 주 콘텐츠에 도달할 방법이 퀴즈 정답의 부수효과뿐**
- **Why it matters**: `TripCard.tsx`에 클릭 핸들러·링크·role·tabindex가 전혀 없다(직접 확인: 클릭해도 무반응, 포커스 가능 요소 0개). 나들이 기록에 도달하는 유일한 경로는 퀴즈 모달의 `onConfirmSuccess` 내부에서 호출되는 `navigate(buildDeviceTripDetailPath(...))`뿐이다. "그냥 기록만 보기"는 게이트를 인정하더라도 존재해야 하는데 없다. 키보드·스크린리더 사용자는 아예 접근 불가.
- **Fix**: 카드 자체(또는 카드 위 명시적 "기록 보기" 액션)에 실제 내비게이션 어포던스를 부여한다. 잠금 게이트는 유지해도 되지만, 카드에서 포커스 가능하고 클릭 가능한 무언가가 반드시 어딘가로 이어져야 한다.
- **Suggested command**: `/impeccable harden` (핵심 플로우의 도달 불가능 경로 수정) 또는 `/impeccable layout` (카드 상호작용 구조 재설계)

**[P0] 다크 테마에서 나들이 카드의 잠금 배지·CTA가 실측 WCAG 위반 + 완전 가림 상태**
- **Why it matters**: 다크 테마 `/main/map`에서 흰색 텍스트/아이콘이 `#cfcecf`(밝은 회색) 배경 위에 얹혀 실측 대비 1.6:1(요구 4.5:1)로 렌더된다 — 라이트용으로 만든 배지 배경이 다크 테마 전환 시 갱신되지 않았다는 뜻. 같은 카드 안에서 "퀴즈 풀기" CTA 텍스트는 썸네일 레이어 아래 완전히 가려져 DOM엔 있지만 화면엔 보이지 않는다. 위 P0(카드가 유일한 진입점)과 결합하면, 다크 테마 사용자는 진입점 자체를 볼 수 없는 상태가 된다.
- **Fix**: 잠금 배지 배경을 다크 테마 토큰(`--color-*-dark`)으로 전환하고, CTA 텍스트를 가리는 z-index/레이어 순서를 카드 컴포넌트에서 바로잡는다. 다크 테마 전체에 대해 카드류 컴포넌트의 실측 대비를 한 번 더 스윕할 것.
- **Suggested command**: `/impeccable audit` (다크 테마 대비 전수 재검사) 후 `/impeccable polish`

**[P0] Seoul Glass 반투명 크롬이 자기 콘텐츠와 충돌 — 데스크톱 프로필 팝오버 + 모바일 하단 탭바 두 곳**
- **Why it matters**: 데스크톱 프로필 팝오버(`background: rgba(255,248,248,0.62)`, `blur(16px)`)는 아래 캘린더 툴바의 텍스트가 비쳐 팝오버 자체의 "사용자 정보 수정" 행과 겹친다. 모바일 하단 탭바(`rgba(255,248,248,0.42)`, `blur(4px)`)는 스크롤 콘텐츠에 하단 여백이 확보되지 않아 "홈"·"나들이" 탭 라벨과 페이지 텍스트가 물리적으로 겹친다. 디텍터가 독립적으로 잡은 `gpt-thin-border-wide-shadow`가 헤더·탭바 네 곳 모두에서 반복 발생해, 이것이 우연한 한 화면의 문제가 아니라 반복되는 컴포넌트 습관임을 뒷받침한다.
- **Fix**: 팝오버·탭바의 불투명도를 90% 이상으로 올리거나 블러 반경을 키워 배경 휘도가 자기 텍스트 대비를 깨지 않게 한다. 캘린더 등 스크롤 콘텐츠에는 하단 고정 내비 높이만큼 `padding-bottom`을 확보한다.
- **Suggested command**: `/impeccable polish`

**[P1] `/main/calendar`가 "일정 없음"과 "로딩 실패"를 구분하지 못함**
- **Why it matters**: 2026년 8월처럼 일정이 없는 달은 완전히 빈 그리드만 보여준다. `/main/map`의 검색 0건 상태(아이콘 + 설명 문구)가 이미 올바른 패턴을 갖고 있음에도 캘린더에는 적용되지 않았다. 실제 사용자가 "고장난 건가?"를 의심하게 만든다.
- **Fix**: 빈 달에 "이 달엔 기록된 일정이 없어요" 같은 짧은 안내를 넣어 `/main/map`의 빈 상태 패턴을 그대로 재사용한다.
- **Suggested command**: `/impeccable onboard` (빈 상태 설계) 또는 `/impeccable clarify`

**[P2] `TripCard`와 `TravelCard`의 상호작용 모델이 동일한 시각 문법 안에서 서로 다름**
- **Why it matters**: 두 카드는 헤어라인 테두리, 라운드 코너, 흰 서피스 등 동일한 시각 언어를 쓰지만 `TravelCard`는 진짜 `<Link>`이고 `TripCard`는 아무 반응이 없다. 커서나 호버 등 구분 신호가 전혀 없어 첫 방문자는 어느 그리드가 클릭 가능한지 예측할 수 없다.
- **Fix**: 나들이 카드를 키보드/클릭으로 프리뷰까지 이동 가능하게 만들어 여행 카드와 통일하거나, 카드 전체에 명확한 잠금 오버레이를 씌워 "게이트된 카드"임을 시각적으로 다르게 만든다.
- **Suggested command**: `/impeccable layout`

# Persona Red Flags

**Alex (파워 유저)**: 나들이 상세로 가는 키보드 경로가 전무하다(카드에 포커스 가능 요소 0개). 단축키, 빠른 추가, 최근 항목 없음. 이미 알고 있는 기록을 볼 때마다 매번 퀴즈를 다시 풀어야 하며 "이건 이미 아니까 건너뛰기" 탈출구가 없다.

**Jordan (첫 방문자)**: `/main/map`에서 두 카드가 완전히 클릭 가능한 여행 카드와 동일한 문법으로 렌더된다. 카드 본문·제목을 클릭해도 커서 변화도 반응도 없다. 유일한 단서는 썸네일 구석의 작은 "퀴즈" 배지뿐이며, 왜 잠겨 있는지는 퀴즈 모달을 열어야만 설명("맞히면 지도가 열려요")된다.

**Sam (접근성/키보드)**: `/main/map` 카드는 탭 순서에 아예 없다. 다크 테마에서는 그 카드의 잠금 배지가 1.6:1 대비로 WCAG AA(4.5:1)를 위반하고, CTA 텍스트는 DOM엔 있지만 시각적으로 완전히 가려져 스크린리더 사용자와 저시력 사용자 모두에게 이중으로 불리하다. 프로필 팝오버의 유리 번짐도 저대비 텍스트 겹침이라는 같은 계열의 문제다.

# Minor Observations

- 캘린더 관리 모달: "기록"(핑크)·"아영"(블루) 두 캘린더 토글이 둘 다 동일한 핑크로 렌더되어, 앱 다른 곳의 색상 구분이 관리 화면에서 끊긴다.
- `일정 추가` 모달이 9개 필드(제목/캘린더/설명/장소/종일/시작일시/종료일시)를 구획 없이 한 스크롤에 노출 — 필수 항목 위주로 먼저 보여주고 설명/장소는 점진적으로 노출하는 편이 좋다.
- `/main/shoesRecom` 헤드라인 "서울 촌놈's 신발 추천"의 영어 소유격+한국어 혼용은 앱의 캐주얼한 톤과는 맞지만, 의도적 카피 선택인지 한 번 점검할 가치가 있다.
- `repeating-stripes-gradient` 디텍터 findings는 추가 조사가 이뤄지지 않아 실제/오탐 여부 미확정으로 남는다.
- 실제 삭제/파기 확인 다이얼로그(나들이·여행 기록)는 이번 조사 범위에서 발견되지 않아, 고위험 액션에서의 안심 장치가 실제로 존재하는지 확인하지 못했다.

# Questions to Consider

1. 퀴즈 잠금이 두 사람만의 친밀함 장치라면, 왜 그 개념 자체는 모달을 열기 전엔 어디에도 설명되지 않고, 왜 "이미 아는 기록이니 건너뛰기" 경로가 없는가?
2. `TripCard`(죽음)와 `TravelCard`(생동)의 시각적 동일함은 실수인가, 아니면 "게이트 전엔 비활성처럼 보여야 한다"는 의도인가 — 후자라면 지금의 헤어라인 카드 문법 자체가 "클릭해보라"는 잘못된 약속을 하고 있지 않은가?
3. 다크 모드가 이제 켜졌으니, 모든 `backdrop-filter` 표면을 정적 목업이 아니라 실제 스크롤 콘텐츠 위에서 대비·겹침을 전수 재검사할 계획이 있는가 — 이번 조사에서 테스트한 두 유리 표면(팝오버, 모바일 탭바) 모두 실제 콘텐츠 앞에서 실패했다.
