## 디자인 특이성 판정

**본문은 제품 고유적이고, 전역 셸은 카테고리 교환 가능하다.** `만난 지 N일째`, 예정 → 오늘 → 지난 기록, 날짜 레일, 여행 사진과 나들이 로고의 비대칭 처리는 이 두 사람의 기록 제품에 맞다. 반면 데스크톱의 거대한 유리 캡슐 헤더와 모바일의 플로팅 유리 pill 내비게이션은 여행·웰니스·개인 CRM 어디에도 붙일 수 있는 범용 AI 앱 셸이다.

자동 탐지기는 `HomeHubPage.tsx`와 `HomeTimelineRow.tsx`에서 0건을 반환했다. 홈 범위의 카드/중첩 카드/카드 그리드/그라디언트/글로우/장식 아이콘 타일은 모두 0건이었다. 이는 본문에 대한 정확한 판정이다. 탐지 범위 밖인 전역 셸은 실제 computed style에서 데스크톱 9999px pill 요소 7개, 모바일 3개, 프로필 아바타 그라디언트 1개, 데스크톱 헤더와 모바일 하단 바의 다중 inset/cast shadow가 확인됐다.

## 보존해야 할 것

### 제품 기능상 반드시 유지

- 고정 기준일을 쓰는 `만난 지 N일째` D-day
- 예정 일정의 날짜·요일·제목·시간·장소와 달력 이동
- 나들이/여행 상세로 직접 가는 기록 행
- 여행 커버, 나들이 로고, 한 줄 리뷰의 실제 사용자 콘텐츠
- 로딩 스켈레톤, 전체 오류 재시도, 계획 없음/기록 없음 CTA
- `/main`과 `/mobile`의 동등한 기능, 프로필 및 네 전역 영역으로의 경로
- 상세/등록 흐름 안의 둘만의 나들이 퀴즈와 한국어의 조용한 카피 톤

`Choi's Film Art`는 현재 진입점이지만 제품 문맥상 필수라고 확인되지 않았다. 재설계 전에 보존 여부를 다시 결정할 수 있다.

### 정보 구조상 반드시 유지

- 홈을 KPI 대시보드가 아니라 **시간순 기록 허브**로 두는 원칙
- 예정 → 오늘 → 지난 기록의 한 방향 읽기 흐름
- 날짜 레일을 독립 축으로 두고 제목·메타·미디어를 연결하는 구조
- 나들이, 여행, 달력의 개념적 분리와 각 상세로의 직접 진입
- D-day를 상단의 사적 맥락으로 두되 통계 카드로 만들지 않는 방식
- 신발 아카이브 기능은 유지하되 기록보다 낮은 정보 우선순위

## 현재 디자인에서 잘 된 부분

1. **카드화를 거부한 시간축**: 단일 컬럼과 날짜 레일은 generic dashboard가 아니라 함께 보낸 시간을 읽게 한다.
2. **의도적인 비균일성**: 텍스트 기록은 촘촘하고 여행 사진은 크게 쉬어 간다. CSS도 `space-6`과 `space-10`을 구분하며 uniform spacing을 피한다.
3. **절제된 미디어 위계**: 여행 사진 하나만 큰 그림자와 면적을 얻고, 나들이 로고는 작은 표식으로 남는다. nested-card와 decorative tile 없이 실제 콘텐츠가 무게를 얻는다.
4. **정서적 제품 사실의 조용한 배치**: D-day가 KPI 배지나 컬러 카드가 아니라 제목 아래 한 문장이라 사적이고 과장되지 않는다.

## AI-generated UI처럼 느껴지는 부분

- 데스크톱 전체 폭의 9999px 글래스 캡슐 헤더, pill 내비게이션 링크, 원형 아바타가 하나의 glassmorphism 프리셋처럼 묶인다.
- 모바일 하단 바의 pill 외곽, blur, inset highlight, 분홍 cast shadow가 기능보다 재질을 먼저 보이게 한다.
- 프로필 아바타의 분홍 그라디언트와 glow는 정보가 없는 장식이다. 프로필 버튼 자체는 기능적이지만 현재 처리는 decorative icon bubble에 가깝다.
- 1440px에서 704px 타임라인만 중앙에 놓여 좌우가 크게 비는 구성은 “모바일 컴포넌트를 데스크톱 캔버스에 올린” 인상을 준다.
- 전역 셸은 정교하지만 제품의 서울·두 사람·기록이라는 사실을 거의 말하지 않아 다른 라이프스타일 앱과 교환 가능하다.

엄격히 구분하면, **generic SaaS dashboard·card-grid·nested-card·decorative icon tile·uniform spacing은 홈 본문에 없다.** 새 디자인은 이를 없애는 작업이 아니라, 이미 잘 피한 선택을 계속 지키는 작업이다. gradient/glow와 excessive rounded corners는 전역 셸에서만 실재한다.

## 우선순위 이슈

1. **[P1] 범용 글래스 앱 셸이 고유한 본문을 덮음**  
   헤더와 하단 바가 첫인상을 장악해 기록 아카이브보다 AI 라이프스타일 앱으로 보인다. 기능적 목적지는 유지하되, 전폭 pill·blur·inset shadow·아바타 그라디언트를 제거하고 평평한 내비게이션으로 재구성해야 한다. 제안 명령: `$impeccable shape`.

2. **[P1] 첫 화면의 감정적 고점이 약함**  
   D-day는 작고 최신 여행의 사진·회고는 일정 목록 아래에서 늦게 나타난다. 첫 화면에서 “다시 그날을 보는” 감정이 발생하지 않는다. 최신/의미 있는 기록의 사진과 한 문장을 우선 노출하되 별도 카드 그리드로 분해하지 않아야 한다. 제안 명령: `$impeccable shape`.

3. **[P1] 데스크톱이 독립된 공간 구성이 아니라 좁은 모바일 목록처럼 보임**  
   1440px에서 본문이 704px로 고정돼 큰 잉여 공간이 생긴다. 타임라인 축은 보존하되 사진, 예정 맥락, 기록 흐름이 데스크톱 너비를 의미 있게 쓰도록 재조합해야 한다. 제안 명령: `$impeccable layout`.

4. **[P2] 기록 종류와 다음 행동의 우선순위가 약함**  
   schedule/trip/travel이 유사한 행으로 보이고 `AYO`/`RYU`는 신규 사용자가 해석해야 한다. 모바일 빈 상태 CTA는 실제 약 18px 높이의 인라인 텍스트다. 카드나 아이콘 타일을 추가하지 말고 타이포그래피·라벨·44px 터치 영역으로 차이를 명확히 해야 한다. 제안 명령: `$impeccable clarify`, `$impeccable adapt`.

5. **[P2] 부분 실패가 빈 상태로 오해될 수 있음**  
   `isError`가 세 데이터 소스가 모두 실패할 때만 참이라 일부 API 실패 시 기록이 조용히 누락된다. 예정 목록은 오류 판단보다 먼저 빈 상태를 렌더링할 수 있다. 재설계에서는 실제 빈 상태와 실패 상태를 배타적으로 표시하고 부분 실패를 명시해야 한다. 제안 명령: `$impeccable harden`.

## 새로운 디자인에서 절대 반복하지 말아야 할 패턴

- KPI/통계 카드로 D-day와 기록 수를 나열하는 generic SaaS dashboard
- 나들이·여행·달력·신발을 동일 크기 카드 4개로 만드는 card-grid
- 사진 카드 안에 메타 카드·CTA 카드·퀴즈 카드를 겹치는 nested-card
- 모든 컨테이너·내비게이션·필터를 pill 또는 24px 이상 라운드로 만드는 방식
- 콘텐츠 뒤의 분홍 radial gradient, glow orb, mesh, 유리 blur
- 기능 없는 아이콘을 색면 타일 안에 넣어 섹션 제목처럼 반복하는 방식
- 모든 행과 섹션에 같은 24/32px 간격을 적용해 기록의 시간 밀도를 지우는 uniform spacing
- 퀴즈를 공개 서비스식 streak·badge·progress ring으로 일반화하는 방식
- 외부 링크, 공유, 소셜 프루프, 사용자 수 지표를 기록보다 앞세우는 방식

## 인지 부하와 감정 여정

인지 부하는 중간 수준이다. 단일 읽기 흐름·그룹핑·점진적 공개는 통과하지만, 데스크톱은 4개 메뉴+프로필, 모바일은 5개 탭으로 한 의사결정 지점에서 권장치 4개를 넘는다. 감정 여정은 따뜻한 D-day로 시작하고 시간축을 쉽게 이해하지만, 첫 사진과 회고가 늦어 정서적 고점이 약하다. 종료부의 Film Art 링크도 아카이브 흐름의 감정적 마침표가 되지 못한다.

## 페르소나 레드 플래그

- **Sam(키보드/저시력 사용자)**: 기록 행의 포커스는 좋지만 인라인 빈 상태 CTA의 포커스/터치 면적이 약하고, 부분 실패가 보조기술 사용자에게 상태로 전달되지 않는다.
